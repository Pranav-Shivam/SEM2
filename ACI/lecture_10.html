01

First-order logic — the worldview

foundation

Propositional logic assumes the world contains facts. First-order logic (predicate logic) assumes the world contains objects, relations among them, and functions that map objects to objects — the same ontology natural language uses.

Building blockExamples
Objectspeople, houses, numbers, colors, baseball games, wars…
Relationsred, round, prime, brother of, bigger than, part of, comes between…
Functionsfather of, best friend, one more than, plus…
∀x Student(x) ⇒ Likes(x, Mathematics) one sentence covers the whole class — propositional logic would need one symbol per student
Cannot say in PL "Some students are brilliant"
"All women are beautiful"
— instructor's own examples for why ∀/∃ exist
Can say in FOL ∃x Student(x) ∧ Brilliant(x)
∀x Woman(x) ⇒ Beautiful(x)
same ∀+⇒ / ∃+∧ pairing as the rest of this lecture
Research notes + recording FOL sits between propositional logic (least expressive, fully decidable) and higher-order / description logics (more expressive, often undecidable). Modern AI "does it in different ways, but it all boils down to these inferencing techniques" — given rules, deduce new insights. Any FOL expression loosely has a subject (the term) and a predicate (the property asserted).

Beginner trap Predicates return a truth value (Brother(x,y)) and can stand alone as sentences. Functions return an object (Father(x)) and can only appear as terms/arguments — never alone as a sentence. In kinship domains, Mother(x) is a function because every person has exactly one biological mother; a predicate could allow zero or many.
03

Truth in FOL — models & interpretation

semantics

A propositional model is just T/F assignments. A first-order model is richer: a domain of objects plus an interpretation that anchors every symbol.

PieceWhat it maps
Constant symbols→ objects in the domain
Predicate symbols→ relations (sets of tuples)
Function symbols→ functional mappings on the domain
An atomic sentence predicate(term₁,…,termₙ) is true iff the objects referred to by the terms are in the relation referred to by the predicate. Equality is special: term1 = term2 is true iff both terms denote the same object.
AIMA's running model — Richard & King John

Domain ≈ 5 objects (R, J, two left legs, crown). Unary: Person, King, Crown. Binary: Brother, OnHead. Function: LeftLeg. Same model reused for UI/EI examples later.

04

Quantifiers — ∀ and ∃

the key upgrade

Universal claims everything; existential claims at least one. The connective pairing is the single most-tested trap in FOL translation.

∀x Man(x) ⇒ Drink(x, Coffee) ∀ + ⇒ — "all men drink coffee"
Semantically ≈ conjunction over the domain:
P(o₁) ∧ P(o₂) ∧ … ∧ P(oₙ)
∃x Boy(x) ∧ Intelligent(x) ∃ + ∧ — "some boys are intelligent"
Semantically ≈ disjunction over the domain:
P(o₁) ∨ P(o₂) ∨ … ∨ P(oₙ)
The connective traps Writing ∀x Man(x) ∧ Drink(x,Coffee) asserts everything is both a man and a coffee drinker. Writing ∃x Boy(x) ⇒ Intelligent(x) is true whenever any non-boy exists — trivially true, useless. Memorize: ∀ pairs with ⇒ · ∃ pairs with ∧.
∀x At(x,BITS) ⇒ Smart(x) Everyone at BITS is smart — expands to At(KingJohn,BITS)⇒Smart(KingJohn) ∧ At(Richard,BITS)⇒Smart(Richard) ∧ At(BITS,BITS)⇒Smart(BITS) ∧ …
∃x At(x,NUS) ∧ Smart(x) Someone at NUS is smart — expands to a disjunction of ground conjunctions
Domain reminder ∀ ranges over the entire domain — including the institution BITS itself as an object. Careful type design (e.g. restricting to Person(x)) avoids unintended conjuncts like At(BITS,BITS) ⇒ Smart(BITS).

Slide examples — informal → stricter FOL

Page 15 of the deck shows two classroom translations. The slide forms are shorthand; the right column is the stricter reading you should write in an exam.

Constants vs variables Prof John, ML, and WILP Students are specific named individuals — a ground atomic sentence, no quantifier needed. "All products" needs a variable + ∀ + ⇒. Deciding constant vs variable is half the translation battle.
05

Properties of quantifiers

exam favourite

Same-quantifier pairs commute. Mixed-quantifier pairs do not. Duality is De Morgan's laws lifted to (possibly infinite) domains.

ClaimStatus
∀x ∀y ≡ ∀y ∀xSame
∃x ∃y ≡ ∃y ∃xSame
∃x ∀y ≢ ∀y ∃xDifferent meanings
Flip the order — does the meaning change? classic exam trap

∀x Likes(x,IceCream) ≡ ¬∃x ¬Likes(x,IceCream) ∃x Likes(x,Broccoli) ≡ ¬∀x ¬Likes(x,Broccoli) quantifier duality — push ¬ inward past ∀/∃ by flipping the quantifier
Why duality matters later Resolution-based provers require CNF. Converting FOL to CNF repeatedly pushes negations inward past quantifiers using exactly these identities — the same De Morgan step from last session, now with ∀/∃.
06

Instantiation — UI, EI & Skolem

inference rules

Universal Instantiation substitutes any ground term. Existential Instantiation invents a brand-new Skolem constant — once only.

∀v α   ⊢   Subst({v/g}, α) Universal Instantiation — for any ground term g (constant or nested function)
∀x King(x) ∧ Greedy(x) ⇒ Evil(x)   yields:
  King(John) ∧ Greedy(John) ⇒ Evil(John)
  King(Richard) ∧ Greedy(Richard) ⇒ Evil(Richard)
  King(Father(John)) ∧ Greedy(Father(John)) ⇒ Evil(Father(John))
∃v α   ⊢   Subst({v/k}, α) Existential Instantiation — k must be a fresh constant never used in the KB
∃x Crown(x) ∧ OnHead(x, John)   yields:
  Crown(C1) ∧ OnHead(C1, John)     # C1 = Skolem constant
Critical differences UI can be applied repeatedly and never loses information. EI can be applied once per existential, only with a new symbol — reusing an existing constant could assert a false identity. Nested under ∀ (∀x ∃y P(x,y)), Skolemization needs a Skolem function f(x), not a plain constant — the witness for y may differ for each x.
07

Reduction to propositional inference

propositionalization

Instantiate every universally quantified sentence with every ground term from the KB. The result is a propositional KB — then any propositional method applies. This is the bridge from UI to why chaining is needed.

# Original FOL KB
∀x King(x) ∧ Greedy(x) ⇒ Evil(x)
King(John)
Greedy(John)
Brother(Richard, John)

# After instantiating ∀ in all possible ways (constants John, Richard)
King(John) ∧ Greedy(John) ⇒ Evil(John)
King(Richard) ∧ Greedy(Richard) ⇒ Evil(Richard)
King(John)
Greedy(John)
Brother(Richard, John)

# Proposition symbols: King(John), Greedy(John), Evil(John), King(Richard), …
From this propositionalized KB you can already conclude Evil(John) by Modus Ponens — same answer FOL forward chaining would give, without ever leaving propositional inference.
Why this does not scale Add even one function symbol (Father) and the Herbrand universe becomes infinite: John, Father(John), Father(Father(John)), …. Full propositionalization may never terminate. Herbrand's theorem: if α is entailed, some finite subset proves it — but there is no bound in advance (semi-decidability). Forward/backward chaining fix this by instantiating only as needed via unification.

Colonel West — the knowledge base

worked example

The law says it is a crime for an American to sell weapons to hostile nations. Nono, an enemy of America, has some missiles, all sold to it by Colonel West, who is American. Prove West is a criminal.

English (from the problem)FOL definite clause
Crime for an American to sell weapons to hostile nationsAmerican(x) ∧ Weapon(y) ∧ Sells(x,y,z) ∧ Hostile(z) ⇒ Criminal(x)
All of Nono's missiles were sold to it by WestMissile(x) ∧ Owns(Nono,x) ⇒ Sells(West,x,Nono)
Missiles are weaponsMissile(x) ⇒ Weapon(x)
Hostile means enemy (of America)Enemy(x,America) ⇒ Hostile(x)
West, who is AmericanAmerican(West)
Nono, an enemy of AmericaEnemy(Nono,America)
Nono has some missiles → EI / SkolemOwns(Nono,M1) · Missile(M1)
# Assembled rule base
1. American(x) ∧ Weapon(y) ∧ Sells(x,y,z) ∧ Hostile(z) ⇒ Criminal(x)
2. Missile(x) ∧ Owns(Nono,x) ⇒ Sells(West,x,Nono)
3. Missile(x) ⇒ Weapon(x)
4. Enemy(x,America) ⇒ Hostile(x)

# Known facts
Missile(M1)          Owns(Nono, M1)
American(West)       Enemy(Nono, America)
Definite clauses & GMP Each rule is a definite clause: exactly one positive literal, written as (p₁∧…∧pₙ) ⇒ q. Generalized Modus Ponens: if the premises unify with known facts under θ, conclude qθ. Facts like American(West) are definite clauses with an empty premise. Clause C in the Curiosity puzzle (negated conclusion) is not definite — chaining alone cannot handle it; resolution can.
10

Forward chaining — step through it

interactive

Data-driven: start from facts, fire every rule whose premises match, add conclusions, repeat until the query appears or nothing new fires. AIMA's FOL-FC-ASK.

StepAlgorithm (slide)Efficiency concern (annotated)
1Start from the factsConjunct ordering
2Trigger all rules whose premises are satisfiedPattern matching (→ Rete)
3Add the conclusion to known factsIrrelevant facts
4Repeat till no new facts or query answeredRedundant rule matching
Colonel West · forward chaining Iteration 0

Efficiency bottlenecks (AIMA §9.3) Conjunct ordering — match most-constrained premise first. Pattern matching — Rete algorithm rematches only changed facts (~90% of naïve rule-engine time is matching). Irrelevant facts — FC derives everything; hybrid with a backward relevance pass helps. Redundant matching — incremental FC only checks newly added facts.
From the recording — PL vs FOL technique count Propositional logic needed four engines (truth table, theorem proving, PL resolution, DPLL) because sentences stay flat. Once you have definite clauses over predicates, forward chaining alone is enough for data-driven growth of the KB — fire rules, add conclusions, ask again. Backward chaining is the query-shaped twin of the same idea.

Backward chaining — step through it

interactive

Goal-driven: start from the query, decompose into subgoals via rules, unify against facts until every leaf succeeds. Depth-first AND-OR search — the engine behind Prolog.

StepAlgorithm (slide)
1Form definite clauses
2Start from the goals
3Search through rules to find the fact that supports the proof
4If it stops at a fact already known → empty set on the LHS (subgoal discharged)
Divide & conquer strategy Substitution by unification
Colonel West · backward chaining Step 0

AspectForward chainingBackward chaining
DirectionData-driven (facts → goal)Goal-driven (goal → facts)
SearchBreadth-like fixed-point iterationDepth-first AND-OR
MemoryCan accumulate all derivable factsLinear in proof size
Best forContinuous data / monitoringSpecific queries · Prolog
WeaknessIrrelevant facts · rematchingRepeated subgoals · loops on recursion
Unification & MGU Matching Weapon(y) against rule head Weapon(x) yields substitution {x/y}; later Missile(y) meets fact Missile(M1) → {y/M1}. The composed substitution is the Most General Unifier (MGU). The occurs check rejects bindings like x ↦ f(x) that would create infinite terms — some Prolog implementations skip it for speed (rarely unsound).

Curiosity killed the cat?

exercise

Jack owns a dog. Every dog owner is an animal lover. No animal lover kills an animal. Either Jack or Curiosity killed the cat Tuna. Did Curiosity kill the cat?

A. (∃x) Dog(x) ∧ Owns(Jack,x)
B. (∀x) ((∃y) Dog(y) ∧ Owns(x,y)) ⇒ AnimalLover(x)
C. (∀x) AnimalLover(x) ∧ (∀y) Animal(y) ⇒ ¬Kills(x,y)
D. Kills(Jack,Tuna) ∨ Kills(Curiosity,Tuna)
E. Cat(Tuna)
F. (∀x) Cat(x) ⇒ Animal(x)
Q. Kills(Curiosity, Tuna)   # the query
Proof walkthrough Step 0 of 5

—
Why chaining alone is not enough Clause C has a negated conclusion (¬Kills) — not a definite clause. Forward/backward chaining (GMP) need a single positive conclusion. Full resolution after CNF conversion (Skolemize, De Morgan, resolve until empty clause) is the general tool — the same contradiction + empty-set idea from PL resolution in session 9/10. The walkthrough above reaches the same answer informally via GMP + disjunctive syllogism.
Exam shape from the recording Expect a worded English problem: translate → (if propositional) CNF → resolution or DPLL; or (if first-order) definite clauses → FC/BC. Instructor: "These type of problems you can expect in the exam." Practice on the slide exercises first; solutions get posted after discussion, not immediately.

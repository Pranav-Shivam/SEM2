01

Classification → Per-Pixel Prediction

Slides 1–2

Intuition — from "one label" to "one label per pixel"

Until now, a CNN's job ended with a single answer for the whole image: squeeze H×W×C down to a 1×1×F vector — "this image is 80% cat." That's classification. Semantic segmentation asks a harder question at every one of the H×W pixel locations simultaneously: which class does THIS pixel belong to? The output is no longer a vector — it's an image-shaped tensor H×W×F, one F-way probability distribution per pixel.

Think of it as the difference between a sticky note ("there's an animal somewhere in this photo") and colouring inside the lines of a colouring book (every pixel gets its own colour). The slide deck frames this with three motivating questions: which pixels are a cat (segmentation), how far is each pixel from the camera (depth), which pixels are fake (forgery detection) — all three share the same "image → image-shaped tensor" shape.

Slide 2 — verbatim definition

"Each pixel has label. Usually visualized by colors. Note: don't distinguish between object instances." Two people in a photo both get the same "person" colour — semantic segmentation does not separate individual object instances. That job belongs to instance segmentation (e.g. Mask R-CNN) or panoptic segmentation (class + instance together).

Per-pixel loss (Slide 2)
Pipeline: H×W×3 → CNN → H×W×F (F class-score channels, same spatial size as input) Loss at EVERY pixel i (standard softmax cross-entropy): Li = −log( exp((Wx)yi) / Σk exp((Wx)k) ) Total loss = sum/average over all H×W pixels, backprop'd together.
Why This Matters

A 128×128 image with 10 classes is really 16,384 independent classification decisions feeding one shared loss. That's the entire conceptual jump this session makes — everything from here (FCN, U-Net, mIoU) exists to make that per-pixel prediction accurate and efficient.

Worked Examples
A segmentation network takes a 64×64×3 input and has F=5 classes. What is the output tensor shape, and how many independent per-pixel classification decisions are made per forward pass?

  1. Output shape mirrors input spatial size, channel = number of classes: 64×64×5.

  2. Number of per-pixel decisions = H×W = 64×64 = 4,096.

AnswerOutput = 64×64×5; 4,096 per-pixel classification decisions, each contributing one softmax cross-entropy term to the total loss.
Why can't classification-style accuracy (mean over one label per image) be used to grade a segmentation model directly?

  1. Classification accuracy assumes ONE ground-truth label per image; segmentation ground truth is a full H×W label map.

  2. The natural analogue is per-pixel accuracy: mean(ŷ = y) computed over all H×W pixels — this is covered formally in Section 05.

AnswerYou need a per-pixel or per-region metric (pixel accuracy, mIoU) — a single whole-image label comparison doesn't exist in this task.
02

FCN — Reusing Classifiers as Segmenters

Slide 3

The trick: FC layer = 1×1 convolution

How do you turn an ImageNet classifier (built to output ONE vector for the whole image) into something that outputs a grid of predictions? Long et al.'s key insight (Fully Convolutional Networks, CVPR 2015): once a classifier's feature map has been shrunk to spatial size 1×1, its final fully-connected layer is mathematically identical to a 1×1 convolution. Once you see that, nothing stops you from feeding in a bigger image — the same conv/pool operations just slide over more area, and instead of collapsing to a single 1×1 point you get a small spatial grid of class scores (e.g. 10×10) for free, using the exact same trained weights.

Convolution output size (used throughout this session)
O = ⌊(W − K + 2P) / S⌋ + 1 W=input size, K=kernel, P=padding, S=stride
Handwritten annotation — reusing a backbone at a bigger input size

The student's margin notes trace exactly this: a 224×224×3 classifier input reduces (via conv/pool) down toward a small spatial grid (≈32×32) before the final 1×1-conv/GAP classification head. Feed in a 500×500 image through the same network instead, and you get a 10×10 grid of class scores rather than one point — "since it's convolution, can reuse an image network" (Slide 3, verbatim).

Why This Matters — transfer learning

This is why segmentation networks are almost never trained from scratch: they inherit an ImageNet-pretrained backbone's learned edge/texture/pattern filters, then fine-tune only the added decoder. FCN (2015) was the first end-to-end pixel-to-pixel CNN for segmentation and set new state-of-the-art on PASCAL VOC while running in under 0.2s per image.

Research Enhanced

Long, Shelhamer & Darrell's FCN paper (CVPR 2015) also introduced the skip architecture that combines a deep, coarse layer with a shallow, fine layer for detailed segmentation — the direct ancestor of the U-Net "copy" connections covered in Section 04. FCN achieved state-of-the-art results on PASCAL VOC, NYUDv2 and SIFT Flow simultaneously, a rare feat for that era. Long et al., CVPR 2015, arXiv:1411.4038

Frequently Tested

The FC → 1×1-conv equivalence

  • State precisely WHEN a fully-connected layer equals a 1×1 convolution (only once spatial size = 1×1).
  • Explain why this lets you run the SAME trained weights on a larger input without retraining from scratch.
  • Know that the output becomes a small spatial GRID of scores, not one vector, when input is enlarged.
03

Upsampling: Unpooling & Transpose Convolution

Slides 4–5

Two ways to go from small back to big

The decoder half of a segmentation network has to reverse whatever the encoder did. Since downsampling used pooling and convolution, upsampling uses their mirror-image operations:

  1. Unpooling (reverse of pooling)

    Nearest-neighbor unpool ×2: copy each value into a 2×2 block. Cheap, parameter-free, but crude — no new detail is invented, and boxy artifacts appear.

  2. Transpose Convolution (reverse of convolution)

    Each single input value scales the entire learned filter and "stamps" it into the larger output canvas at stride-spaced positions; wherever two stamps overlap, their values are summed.

Worked arithmetic (Slides 4–5, verified)
Max-pool 2×2, stride 2 on: [1 1 2 4 / 5 6 7 8 / 3 2 1 0 / 1 2 3 4] → [[6 8] [3 4]] (max of each 2×2 block) Transpose-conv output size: O = (I − 1)×S + K − 2P Example (Slide 5): I=5, S=1, K=3, P=0 → O = (5−1)×1 + 3 − 0 = 7 Solve for stride given O=7, I=5, K=3, P=0: 7 = 4S+3 → S=1

⊞ Interactive · Transpose Convolution — Stamp & Sum

A 2×2 input (I₁₁, I₁₂, I₂₁, I₂₂) stamps a 3×3 filter into a larger output canvas, stride 2. Step through to see the overlap get summed.
Output canvas (5×5)
Research Enhanced

Checkerboard artifacts: when a transpose-conv kernel size isn't evenly divisible by its stride, output pixels get uneven numbers of overlapping stamps — producing a visible checkerboard pattern. The widely-cited Distill.pub article shows this and demonstrates that replacing transpose-conv with "resize (nearest-neighbor) + ordinary convolution" removes the artifact — now a standard fix in many GAN and segmentation decoders.

Odena, Dumoulin & Olah, "Deconvolution and Checkerboard Artifacts," Distill.pub 2016

Worked Examples
Nearest-neighbor unpool ×2 is applied to a 3×3 feature map. What is the output size?

  1. ×2 unpool doubles each spatial dimension: 3×2 = 6.

Answer6×6 — each of the 9 input values is replicated into its own 2×2 block.
Compute the transpose convolution output size for I=5 (input), S=2 (stride), K=3 (kernel), P=1 (padding).

  1. Formula: O = (I−1)×S + K − 2P.

  2. O = (5−1)×2 + 3 − 2×1 = 8 + 3 − 2 = 9.

AnswerOutput = 9×9.
Key Insight

This is the exact mirror of the ordinary-convolution size formula — memorise both, and know which one to invert for the other.

Why detail gets lost — and how U-Net fixes it

Pooling literally throws away fine-grained detail; blowing the bottleneck back up can't recover it. FCN's early results were blurry and mis-aligned with true object edges for exactly this reason (Slide 7). The fix: copy the high-resolution encoder activations directly across to the matching-resolution decoder layer, skipping the bottleneck — then concatenate and let subsequent layers learn how to fuse coarse "what" with fine "where."

Slide 7 — verbatim

"How do you send details forward in the network? You copy the activations forward. Subsequent layers at the same resolution figure out how to fuse things." This IS the U-Net "copy" arrow.

Why This Matters — U-Net's origin story

U-Net (Ronneberger, Fischer & Brox, MICCAI 2015) was built for biomedical images where labeled training data is scarce (expert annotation is expensive). It leaned on heavy data augmentation and won the ISBI cell tracking challenge 2015 by a large margin — segmenting a 512×512 image in under a second. The skip-connection idea proved so effective it's now everywhere: satellite imagery, self-driving perception, and even the denoising backbone of diffusion image generators like Stable Diffusion.

Research Enhanced

Skip connections in U-Net (concatenation) are conceptually related to ResNet's skip connections (addition), both from the same 2015 era, both solving the same underlying problem — information/gradient loss through deep stacks — via different mechanisms.

Ronneberger et al., MICCAI 2015, arXiv:1505.04597

Frequently Tested

U-Net vs plain encoder-decoder

  • Name the exact failure (blurry, misaligned boundaries) that skip connections fix.
  • Know it's concatenation (U-Net) vs addition (ResNet) — don't conflate the two skip mechanisms.
  • U-Net was designed for scarce labeled data (biomedical) — explain why that motivated heavy augmentation.
05

Argmax, Pixel Accuracy & mIoU

Slide 8

From scores to a final label map

The network's output is H×W×F — a full probability distribution at every pixel. To get one final answer per pixel, take argmax across the F channels: whichever class has the highest score at that pixel wins. Do this independently everywhere and you get a clean H×W label map.

⊞ Interactive · Score Tensor → Label Map (Argmax)

A 3×3 patch, 3 classes (Background / Cat / Dog). Step through the per-channel score maps to the final argmax label.
Patch state
Segmentation metrics (Slide 8)
Pixel Accuracy = mean( ŷ = y ) fraction of pixels predicted correctly mIoU = mean over classes of (Prediction ∩ Ground-Truth) / (Prediction ∪ Ground-Truth)
Why This Matters — accuracy is misleading

A lazy model that predicts "background" everywhere can still score high pixel accuracy, since background usually dominates the image, while being useless at finding the actual object. mIoU forces the model to get shape and extent right, and — because it averages per-class IoU BEFORE averaging across classes — small/rare classes get equal weight to large/common ones.

Research Enhanced

mIoU is the standard reported metric on Cityscapes, PASCAL VOC segmentation, and ADE20K precisely for this reason. Classic cautionary example: a self-driving perception model dominated by "road" and "sky" pixels can post high pixel accuracy while badly missing small, safety-critical classes like "pedestrian" — mIoU exposes that failure where raw accuracy hides it.

Cityscapes benchmark, cityscapes-dataset.com/benchmarks

Worked Examples
A ground-truth "cat" mask has 100 pixels; a prediction overlaps it in 60 pixels and also wrongly covers 40 extra non-cat pixels. Compute IoU for the cat class.

  1. Intersection = 60 (correctly-predicted cat pixels).

  2. Union = GT(100) + Pred(60+40=100) − Intersection(60) = 140.

  3. IoU = 60/140 ≈ 0.43.

AnswerIoU ≈ 0.43 for the cat class.
A model gets 95% pixel accuracy on a road-scene image where 90% of pixels are "road" or "sky." Is this a strong result? What single change to the metric would expose weaknesses?

  1. 95% accuracy sounds strong, but if road+sky are 90% of pixels, getting only those right already gives ~90% — the extra 5% covers everything else combined.

  2. Switching to mIoU (per-class IoU averaged) would reveal poor performance on small classes (pedestrian, sign, pole) that plain accuracy hides.

AnswerNot necessarily strong — report mIoU per class instead of aggregate pixel accuracy.
06

IoU, Precision & Recall Foundations

Slides 9–10 Karel Horak, mAP

Bounding-box IoU and the threshold rule

For object detection, IoU works on boxes instead of pixel blobs: overlap area over union area. Datasets pick a threshold — almost always 0.5 for PASCAL VOC — to decide true positive vs false positive.

IoU & Precision/Recall (Slides 9–10, verified)
IoU = area of overlap / area of union TP if IoU ≥ threshold (commonly 0.5) Precision = TP / (TP + FP) "of my predictions, how many were right?" Recall = TP / (TP + FN) "of all real positives, how many did I find?" F1 = 2 · (precision · recall) / (precision + recall)

Handwritten annotation — worked numeric IoU (Slide 10)

GT box (50,50)–(250,200); Predicted box (70,80)–(280,220). Intersection corners: top-left = (max(50,70), max(50,80)) = (70,80); bottom-right = (min(250,280), min(200,220)) = (250,200). Intersection = 180×120 = 21,600. Union = 30,000 + 29,400 − 21,600 = 37,800. IoU = 21,600/37,800 ≈ 0.57 — re-derived and confirmed independently against the slide's own answer.

Research Enhanced

Precision/recall/F1 originate from information retrieval, adopted wholesale into ML evaluation. The IoU≥0.5 rule is a PASCAL VOC (2007–2012) convention still quoted today as "AP50" in modern detector papers. Scale context: PASCAL VOC has ~11,530 images / ~27,450 objects across 20 classes; COCO has 200,000+ images and 1.5 million instances across 80 categories — roughly two orders of magnitude larger, which pushed detectors toward deeper, more data-hungry architectures.

Everingham et al., IJCV 2010 (PASCAL VOC)   Lin et al., arXiv:1405.0312 (COCO)

Worked Examples
A detector makes 10 predictions: 7 are correct (TP), 3 are wrong (FP). There were 9 real objects total. Compute precision and recall.

  1. Precision = TP/(TP+FP) = 7/10 = 0.70.

  2. FN = real objects missed = 9 − 7 = 2. Recall = TP/(TP+FN) = 7/9 ≈ 0.78.

AnswerPrecision = 0.70, Recall ≈ 0.78.
Explain, with the "five apples" style logic, why recall can never decrease as you walk down a confidence-ranked detection list, while precision can go up or down.

  1. Recall = TP-so-far / total-GT. TP-so-far only ever grows or stays flat as you add more detections — never shrinks. So recall is non-decreasing.

  2. Precision = TP-so-far / detections-so-far. A correct detection raises it, a wrong one lowers it at that step — hence the zigzag.

AnswerRecall accumulates monotonically (denominator fixed = GT count); precision is re-evaluated fresh at every rank (denominator grows with every prediction, right or wrong) — hence its zigzag.
07

Average Precision — PR Curve & Interpolation

Slides 10–11

Area under the precision-recall curve

Average Precision is officially the area under the precision-recall curve. But the raw curve zigzags (per Section 06), so before computing area we smooth it: at every recall level, replace precision with the best (max) precision achieved at that recall level or any higher recall. This turns a jagged curve into a clean, monotonically-decreasing staircase.

AP definitions (Slide 11)
AP = ∫₀¹ p(r) dr area under the PR curve p_interp(r) = max over r̂≥r of p(r̂) the smoothing / interpolation rule
Slide 11 — PASCAL VOC rule, verbatim

"For the PASCAL VOC challenge, a prediction is positive if IoU ≥ 0.5. Also, if multiple detections of the same object are detected, it counts the first one as a positive while the rest as negatives." In Pascal VOC2008, an average for the 11-point interpolated AP is calculated.

Why This Matters

The "first detection wins, rest are negatives" rule stops a model from gaming the metric by spamming overlapping boxes around one easy object — an important, frequently-missed detail.

Frequently Tested

Interpolation direction

  • The max is taken over recall ≥ r (looking RIGHT/forward), never over recall ≤ r.
  • This makes the smoothed curve monotonically non-increasing as recall grows — know why (it can only get harder to maintain high precision as you accept more recall).

Why 11-point AP was retired after 2008

Two admitted weaknesses (Slide 13): (1) sampling only 11 fixed points is a rough approximation of the true curve shape; (2) it poorly distinguishes two weak detectors, since low-AP curves collapse most of those 11 samples toward zero. PASCAL VOC 2010–2012 switched to the exact area-under-curve method (Section 09).

Worked Examples
At rank #6 in the worked table, TP-cumulative = 4 and FP-cumulative = 2, with 6 total ground-truth objects. Compute precision and recall.

  1. Precision = 4/(4+2) = 0.667.

  2. Recall = 4/6 = 0.667.

AnswerPrecision ≈ 0.67, Recall ≈ 0.67 (matches the demo above at rank 6).
Rank 11 has IoU = 0.53 (above the 0.5 threshold) yet is marked FP. Why?

  1. By rank 10, all 6 ground-truth objects are already matched (TP-cumulative reached 6).

  2. Rank 11's detection, even with a good IoU, has no unmatched GT left to claim — it's a duplicate.

  3. Duplicates on an already-matched object are always scored FP, regardless of IoU — this stops a detector "cheating" by outputting many boxes around one easy object.

AnswerFP because it's a duplicate detection on an object already claimed by an earlier (higher-confidence) true positive — the "first detection wins" rule from Section 07.
Key Insight

TP count can never exceed the GT count. Always check "is there still an unmatched GT available" before calling something TP purely on IoU.

09

COCO mAP — AUC Method & Multi-IoU Averaging

Slides 14–15

Exact area, then stricter, multi-threshold averaging

VOC2010–2012 replaced 11-point sampling with the exact area under the (smoothed) PR curve — no approximation, sampled at every recall breakpoint where precision drops. COCO then went further: instead of one fixed IoU threshold (0.5), it computes AP at 10 different IoU thresholds (0.5 to 0.95, step 0.05) and averages across all of them — plus it uses 101-point interpolation instead of 11.

AUC & COCO formulas (Slides 14–15)
AP = Σₙ (r_{n+1} − rₙ) · p_interp(r_{n+1}) exact rectangular-block area, no interpolation error COCO AP@[.5:.95] = average AP over IoU = 0.50, 0.55, …, 0.95 (10 thresholds) Also reported: APIoU=.50 (= VOC metric) · APIoU=.75 (strict) · APsmall/medium/large · ARmax=1/10/100

Why This Matters — reading a real results table

In the YOLOv3 paper's COCO table (Slide 15), YOLOv3's AP50 (57.9) is close to Faster R-CNN's, but its overall AP@[.5:.95] (33.0) is noticeably lower — meaning YOLOv3 finds objects with roughly-correct boxes well, but its precise localisation is comparatively weaker. RetinaNet (ResNeXt-101-FPN backbone) beats every two-stage Faster R-CNN variant AND YOLOv3 in that table — the first time a one-stage detector won outright at that scale, thanks to Focal Loss fixing foreground/background class imbalance.

Research Enhanced

COCO's own documentation states: "AP is averaged over all categories. Traditionally, this is called mean average precision (mAP). We make no distinction between AP and mAP (and likewise AR and mAR)." This differs from older VOC-era usage where AP meant per-class and mAP meant averaged-across-classes — a common source of confusion when comparing papers across eras. ImageNet detection instead uses the plain AUC method.

COCO detection evaluation docs, cocodataset.org/#detection-eval   Lin et al., "Focal Loss / RetinaNet," ICCV 2017, arXiv:1708.02002   Redmon & Farhadi, "YOLOv3," arXiv:1804.02767

Frequently Tested

VOC vs AUC vs COCO — don't conflate

  • VOC ≤2008: 11-point interpolated AP (approximate).
  • VOC 2010–2012: exact area-under-curve, no interpolation error.
  • COCO: 101-point interpolated AP, averaged over 10 IoU thresholds (0.5→0.95, step 0.05) — the primary challenge metric.
  • COCO treats "AP" and "mAP" as synonyms; older VOC literature does not.

Conceptual Deep Dives

Five cross-cutting ideas connecting segmentation architecture to evaluation metrics — the "why" questions that separate a distinction answer from a pass.

A · Semantic vs Instance vs Panoptic Segmentation

Semantic segmentation labels every pixel with a CATEGORY only — two people in a photo are both just "person," indistinguishable (Slide 2, explicit). Instance segmentation (e.g. Mask R-CNN) additionally separates individual objects of the same class. Panoptic segmentation does both simultaneously — per-pixel category AND per-instance identity, unifying "stuff" (sky, road — uncountable regions) with "things" (car, person — countable instances). This is one of the most common exam trip-ups: don't say semantic segmentation "finds objects" — it only names regions.

B · Why encoder-decoder needs BOTH resolution loss and skip connections

You might ask: why downsample at all if you're just going to upsample back? Two reasons. First, downsampling grows the receptive field cheaply — each neuron in a shrunk feature map "sees" a larger patch of the original image, letting the network reason about broad context (is this a person-shaped region at all?) rather than only local texture. Second, it makes the network computationally tractable — full-resolution processing at every layer would be prohibitively expensive. The cost is fine detail, and skip connections are the surgical fix for exactly that cost, restoring detail without giving up the cheap, context-aware bottleneck.

C · The IoU threshold as a dial, not a fixed rule

IoU≥0.5 (PASCAL VOC) is a convention, not a law of nature. Raising it to 0.75 or averaging across 0.5–0.95 (COCO) doesn't change what IoU measures — it changes how forgiving the evaluation is about imprecise localisation. A detector can have identical "does it find the object" behaviour under both regimes yet score very differently, because the threshold decides how tightly the predicted box must hug the true one. This single dial is why the same detector reports very different AP50 vs AP75 vs AP@[.5:.95] numbers.

D · mIoU and mAP are the same idea in two different tasks

Both metrics follow the identical recipe: (1) define an overlap measure between prediction and ground truth (IoU); (2) decide a rule for correct/incorrect based on that overlap; (3) average per-class results into one number. mIoU applies this at the pixel-region level for segmentation; mAP applies it at the bounding-box + ranked-confidence level for detection, adding the extra machinery of a precision-recall curve because detections come with a confidence score that segmentation masks typically don't.

Why is mIoU generally preferred over plain pixel accuracy for grading segmentation models?

Q7MediumPrecision/Recall · Slide 10
As you walk down a confidence-ranked list of detections, which statement is true?
  • ABoth precision and recall increase monotonically
  • BRecall increases monotonically; precision can zigzag up or down
  • CPrecision increases monotonically; recall can zigzag
  • DBoth can zigzag freely
Recall's denominator (total GT) is fixed, so it never decreases as TPs accumulate. Precision's denominator grows every step (TP or FP), so a wrong guess drags it down and a right guess pulls it back up.Common mistakeAssuming both metrics behave the same way as rank increases.
Q8MediumAP interpolation · Slide 11
The VOC interpolation rule p_interp(r) = max over r̂≥r of p(r̂) means:
  • AAt recall r, use the best precision achieved at that recall or any HIGHER recall
  • BAt recall r, use the average precision across all recall levels
  • CAt recall r, use the precision from the lowest-confidence detection
  • DAt recall r, use the best precision at any LOWER recall
The max looks forward (r̂ ≥ r), not backward — this is what makes the smoothed curve monotonically non-increasing.Common mistakeReversing the direction (D) — looking at lower recall instead of higher.

01

The Object Detection Landscape

Slides 1-2, 47-49

Intuition first — detection is a family of related questions

"Object detection" is really an umbrella. Generic object detection finds any of many trained categories and draws a box (bounding-box regression). Salient object detection instead asks "what's the single most visually important region?" — no fixed categories, just a soft attention mask (local contrast segmentation). Face detection and pedestrian detection are narrower, specialized versions of generic detection: faces and upright walking people have much more regular, predictable shapes than "any object," so they get extra tricks (multi-scale pyramids for faces of many sizes; boosted/part-based classifiers for pedestrians).

Taxonomy (from Slide 1's mind-map)
Object detection ├─ Generic object detection (bounding-box regression) │ └─ Face detection (multi-scale adaption) └─ Salient object detection (local contrast segmentation) └─ Pedestrian detection (multi-feature / boosting forest)

The "big idea" — attach any head to a CNN feature map

Once a CNN produces a feature map over an image, you aren't limited to "is there an object + where." At any spatial location in that feature map you can attach any prediction head — a class score, a box, a segmentation mask, even a 3D plane equation — as long as you have paired training data for it.

PlaneRCNN (NVIDIA, CVPR 2019) is exactly this idea in practice: it reuses a Mask R-CNN-style detector but swaps the class-label head for four new heads on a boxed region — Plane/No-Plane, Mask, Surface Normal, and Offset (distance from camera) — letting it reconstruct a room's 3D layout from one RGB photo. 02

The R-CNN Family — Two-Stage Detectors

Slides 1, 5-6, 48, 67

Intuition first — propose, then classify

DPM, sliding-window classifiers, and R-CNN are all the same family of idea: propose candidate regions/windows, then run a classifier on each one. DPM (Deformable Parts Model, Felzenszwalb 2008) does this with hand-crafted HOG-like filters — a coarse "root" template for the whole object plus smaller "part" templates that can shift slightly, combined into a response heatmap. R-CNN modernizes this by swapping the hand-crafted classifier for a deep CNN.

R-CNN's 4-step pipeline

  1. Input image

    A raw photo — no pre-processing beyond the usual normalization.

  2. Extract region proposals (~2,000)

    Selective Search generates ~2,000 candidate boxes per image — a classical, non-neural algorithm.

  3. Compute CNN features

    Each proposal is warped to a fixed square and run through its own full CNN forward pass — extremely slow, since there's no shared computation across the ~2,000 proposals.

  4. Classify regions

    Each region's CNN feature vector is classified independently: "aeroplane? no. … person? yes. … tvmonitor? no."

Why This Matters — one bottleneck fixed per generation

R-CNN → Fast R-CNN: stop re-running the CNN per proposal — run it once on the whole image, then RoI-pool each proposal's features from the shared feature map. Fast R-CNN → Faster R-CNN: replace Selective Search (external, CPU, slow) with a small trainable Region Proposal Network that shares the same convolutional features — the whole pipeline becomes one neural net. Faster R-CNN → Mask R-CNN: add one more output branch for a pixel-level mask (instance segmentation), swapping RoIPool for RoIAlign to remove quantization misalignment.

Research Enhanced

Ross Girshick authored R-CNN (2014) and Fast R-CNN (2015), then co-authored Faster R-CNN (2015, with Ren, He, Sun) and Mask R-CNN (2017, with He et al. — ICCV 2017 Marr Prize / Best Paper). Fast R-CNN's RoI Pooling gave roughly a 200× test-time speedup over plain R-CNN by sharing one CNN pass across all proposals. A common misconception: "R-CNN" is often used loosely as a synonym for "any two-stage detector," but the original R-CNN used classical Selective Search for proposals, not a neural network — the "fully neural, fully end-to-end" property only arrived with Faster R-CNN.

Girshick, "Rich feature hierarchies…", CVPR 2014 · Girshick, "Fast R-CNN", ICCV 2015 · Ren, He, Girshick, Sun, "Faster R-CNN", NeurIPS 2015

Why Accuracy Isn't Enough — Speed vs Accuracy

Slides 3-4, 14

Intuition first — a car doesn't pause the world while a network thinks

This is the single most memorable slide in the deck. Imagine a self-driving car that can only "see" once per detector run — how far would it blindly drive while waiting for one image to finish processing? Every distance below uses the same assumption: 60 mph = 88 feet/second, multiplied by each detector's own measured latency (distance = speed × time).

This "blind travel distance" framing is a famous pedagogical device popularized in Stanford CS231n's object-detection lecture and widely reused across CV courses. Exam Radar

Speed vs Accuracy — exam radar

  • Know the arithmetic pattern (distance = speed × time at 88 ft/s), not just the memorized numbers — a variant with a different mph is a common twist.
  • Know WHY R-CNN is slower than DPM despite being far more accurate: it runs a full CNN separately per proposal, no shared computation.
  • Common mistake: assuming "more accurate is always better" — for latency-critical robotics, a slightly-less-accurate-but-far-faster model is the objectively better system-level choice.
04

YOLO — Grid Cells, Boxes & Confidence

Slides 6-9

Intuition first — you only look once

YOLO stops treating detection as "first guess where objects might be, then classify each guess" and instead directly divides the image into a coarse S×S grid and, for every cell, directly outputs a class score and up to B candidate boxes for whatever object is centered there — all in a single forward pass through one ConvNet. Three steps: (1) resize the image, (2) run one convolutional network, (3) threshold detections.

Per-box confidence and the fixed-size output tensor
Per-box confidence: confidence = Pr(Object) × IOUpredtruth If no object in the cell → ideal confidence = 0. If an object exists → ideal confidence = IoU(pred, truth). Class-specific confidence: Pr(Classi|Object) × Pr(Object) × IOUpredtruth = Pr(Classi) × IOUpredtruth Output tensor size, for Pascal VOC (S=7, B=2, C=20): 7 × 7 × (2×5 + 20) = 7 × 7 × 30 = 1470 outputs Each box = 5 numbers (x, y, w, h, confidence); (x,y) relative to the cell, (w,h) relative to the whole image.

Research Enhanced

YOLO (Redmon, Divvala, Girshick, Farhadi, CVPR 2016) ran at 45 FPS (155 FPS for the smaller "Fast YOLO"), the first detector that felt genuinely real-time for video. A classic misconception: "one look" doesn't mean the network only sees a few pixels — it means only one forward pass through one network is needed per image, versus running a classifier separately over thousands of proposed sub-images (R-CNN) or sliding-window crops (DPM/HOG).

05

Training YOLO — Responsible Cell & Predictor

Slides 10-12

The assignment rule, step by step

  1. Find the responsible cell

    During training, locate the ground-truth object's box center. Whichever of the S×S cells that center falls inside becomes "responsible" for that object — all other cells are not blamed for missing it.

  2. Pick the responsible predictor

    That cell predicted B boxes (B=2 for Pascal VOC). Compare each to the ground truth via IoU; whichever has the highest IoU is declared the "responsible predictor" for this object.

  3. Adjust the winner

    The winning box's coordinates are nudged toward the ground truth, and its confidence is pushed up toward 1 (or the actual IoU).

  4. Suppress the loser

    The other (losing) box in that same cell is NOT trained to match this object — its confidence is instead pushed toward 0, since it did not represent the object as well as the winner.

  5. Empty cells → confidence to zero

    Cells with no ground-truth object at all have nothing to compute coordinate/class loss against — only their confidence is pushed toward 0.

Why λnoobj exists
Most of a typical image's cells are empty (background). Without down-weighting, the sheer count of "no object" cells would overwhelm training — the network would trivially minimize loss by predicting zero confidence everywhere. λcoord = 5 (boost coordinate loss for object-containing cells) λnoobj = 0.5 (down-weight confidence loss for empty cells)
Research Enhanced

This "one predictor wins, encourage specialization" design is a form of hard assignment (similar in spirit to hard-EM) — empirically, one box "slot" per cell tends to learn wide-aspect boxes while the other learns tall ones. It directly foreshadows anchor-box matching in every detector since: YOLOv2 assigns objects to specific anchor boxes rather than an unconstrained predictor pair, and this "cell-owns-one-object" bottleneck (which struggles with small, clustered objects like a flock of birds) was itself a major motivation for anchor boxes and YOLOv3's three-scale detection. The foreground/background imbalance λnoobj hand-tunes here is the same fundamental issue that later motivated Focal Loss in RetinaNet (Lin et al., 2017), solved in a more principled, adaptive way.

06

Non-Max Suppression

Slides 9, 13

Intuition first — cleaning up the raw swarm

Every cell in the grid proposes its own candidate boxes simultaneously — for one real object, several neighboring cells often all guess overlapping boxes. NMS's job: sort all candidates by confidence, keep the highest, and suppress (zero out, or discard) any remaining box whose IoU with it exceeds a threshold and which predicts the same class. Crucially, NMS only touches the confidence score / survival of a box — it doesn't "judge correctness," it only removes duplicate detections of an object that's already been found.

Exam Radar

NMS — exam radar

  • NMS operates per class — two overlapping boxes of different classes are never suppressed against each other.
  • Common mistake: thinking NMS "removes wrong detections." It only removes duplicates of an already-found object; a legitimate second object nearby can wrongly get suppressed too (why Soft-NMS exists).
  • Sequence to memorize: sort by confidence → keep top → suppress same-class boxes above the IoU threshold → repeat on what remains.

Evaluation Metrics — IoU & Dice

Slides 17-18

The deck's exact worked example

GT box corners: (50,50) bottom-left, (250,200) top-right. Predicted box corners: (70,80) bottom-left, (280,220) top-right.

  1. GT area = height × width = (200−50) × (250−50) = 150 × 200 = 30000.

  2. Pred area = (220−80) × (280−70) = 140 × 210 = 29400.

  3. Intersection bottom-left = (max(50,70), max(50,80)) = (70,80). Intersection top-right = (min(250,280), min(200,220)) = (250,200).

  4. Intersection area = (200−80) × (250−70) = 120 × 180 = 21600.

  5. Union area = 30000 + 29400 − 21600 = 37800.

  6. IoU = 21600 / 37800 ≈ 0.57.

  7. Dice = 2×21600 / (30000+29400) = 43200 / 59400 ≈ 0.7272.

AnswerIoU ≈ 0.57, Dice ≈ 0.7272. Dice always reports higher than IoU for the same two shapes: Dice = 2·IoU/(1+IoU).

Research Enhanced

IoU = intersection/union; Dice = 2·intersection/(sum of areas). Because Dice puts a factor of 2 on the intersection and divides by the sum of areas (not the union), Dice ≥ IoU always, related by Dice = 2·IoU/(1+IoU). IoU (as "mean IoU") is the standard metric for semantic segmentation and detection box-matching, while Dice dominates medical image segmentation (tumor/organ boundaries) because it's comparatively more forgiving on small structures.

Generalization & Dataset Bias

Slides 14-16

YOLO generalizes to artwork

Surprisingly, YOLO — trained only on photos — also detects people in paintings (Picasso portraits, Munch's "The Scream") reasonably well, even though it never saw a painting during training.

R-CNN's AP collapses on art (54.2 → 10.4) while YOLO barely drops (59.2 → 53.3) — YOLO reasons holistically about the whole image, while R-CNN's region-proposal pipeline leans on photograph-specific local statistics.

From the deck — "A Few Caveats"

"Flickr images come from a really weird process: (1) user takes a picture, (2) user decides to upload it, (3) user decides to write something like 'refrigerator' somewhere in the description, (4) a vision person stumbles on it while searching Flickr for refrigerators for a dataset." — followed by a grid of photos captioned "Who takes photos of open refrigerators?????"

Dataset bias, in three flavors

Selection bias (Flickr fridges): nobody photographs a closed, boring fridge and tags it "refrigerator" — only unusual, camera-conscious shots get tagged that way, so a Flickr-built "refrigerator" dataset is quietly non-representative.

Curation bias ("Kitchens from Googling"): Googling "kitchen" surfaces staged, magazine-style photos, not messy real ones — a model trained on this fails on ordinary kitchen photos.

Texture bias: a >90%-confidence detection on a close-up of leopard-print fabric, misclassified as one of Person/Giraffe/Bicycle — a model can latch onto a superficial texture cue rather than true object structure, and "99% precision on the original dataset" doesn't protect against this on out-of-distribution inputs.

COCO vs PASCAL VOC

COCO (2014) has 80 "thing" categories + 91 "stuff" categories, ~330K images, ~1.5 million instances — versus VOC's 20 categories. COCO also averages mAP over IoU thresholds 0.5 to 0.95 ("AP@[.5:.95]") rather than VOC's single IoU=0.5 threshold, which is why COCO AP numbers (often 28-38) look much lower than VOC mAP numbers (60-80) for comparably strong models — it's measuring a stricter task, not a worse model.

Why This Matters — beyond cars and pedestrians

The Fouhey Lab (University of Michigan) used deep instance segmentation to automatically locate and measure individual bones in photographs of museum bird skeletons — skull, femur, etc. — cutting measurement time roughly 15× versus manual calipers, and enabling trait databases spanning 2,000+ bird species. Same underlying technology as detecting "person" or "bicycle" — pointed at a scientific measurement problem instead.

Zhou, Hassena, Weeks, Fouhey, "Quantifying Bird Skeletons", CVPR Workshops 2021

Conceptual Deep Dives

Compare & Contrast
Why does the accuracy/speed trade-off between R-CNN and YOLO exist structurally, not just as an implementation detail?

  1. R-CNN-family detectors spend a whole separate stage generating and scoring class-agnostic region proposals before classification — that extra stage gives them a chance to refine localization multiple times, at a real compute cost.

  2. YOLO collapses proposal + classification into one regression pass over a fixed grid — no per-region refinement stage — which is exactly what removes the bottleneck but also removes a source of localization accuracy.

  3. So the trade-off isn't a bug in either design — it's the direct consequence of "one stage that always predicts a fixed number of boxes" vs "however many regions a slower proposal step decides to examine."

Key Insight

Every later architecture (SSD, RetinaNet, YOLOv3+) is really an attempt to close this gap from the one-stage side — multi-scale grids, anchor boxes, focal loss — rather than abandoning the single-pass idea.

Why can't more training iterations fix YOLOv1's struggle with small, clustered objects (e.g. a flock of birds)?

  1. YOLOv1's assignment rule hard-codes "one cell owns at most one object" (Section 05). If two objects' centers land in the same or adjacent cells, one is structurally unrepresentable — no amount of extra training data or epochs changes that geometric constraint.

  2. This mirrors RANSAC's degeneracy problem: more iterations only help you find a good sample/fit within a correct model — they can't fix a model that is structurally the wrong shape for the data.

  3. The actual fix was architectural: anchor boxes (YOLOv2) and multi-scale grids (YOLOv3) loosen the one-object-per-cell bottleneck by giving each location multiple, differently-shaped "slots."

Key Insight

A capacity/data problem is fixed by more training; a structural/representational bottleneck needs an architecture change. Learn to tell them apart.

IoU and Dice measure "the same" overlap — when do they diverge, and why does medical imaging prefer Dice?

  1. Dice = 2·IoU/(1+IoU) is a monotonic function of IoU, so they never disagree on ranking — but Dice is always numerically higher for the same shapes, and the gap is largest at low overlap (e.g. IoU=0.33 → Dice=0.5).

  2. For small structures (a tumor a few pixels wide), a 1-2 pixel boundary error is a much bigger fraction of the union than of the sum-of-areas — so IoU punishes small-object boundary noise harder than Dice does.

  3. Medical segmentation targets are frequently small relative to the image, so Dice's comparative forgiveness on small-structure boundary noise makes it the more stable training/reporting metric there, while detection/segmentation on natural images (COCO, VOC) standardizes on IoU.

Key Insight

Same ranking, different sensitivity — pick the metric whose forgiveness profile matches your object sizes.

Why Tables Fail: Generalization & Function Approximation

Intuition first

Tabular learning keeps one row per state in a giant lookup table — fine for tic-tac-toe, hopeless for anything real. Pacman alone has more board configurations than you could ever visit during training, let alone store in memory. The fix RL borrows straight from supervised learning: generalize — learn from a small number of experienced states, and let that experience transfer to states you've never seen, because they share structure with what you've already learned.

The deck's own before/after demo makes this concrete. Run naïve tabular Q-learning on Pacman for 50 episodes and the agent still scores −14 — it keeps wandering into danger because a ghost one square to the left counts as a "brand new, unknown state" to a table. Swap in a parameterized function approximator and, after the same 50 episodes, the score flips to +19. Nothing about the environment changed — only the ability to generalize what "danger near a ghost" means across many pixel-different but conceptually-identical states.

The parameterized value approximator

Represent each state as a vector of features (f1, f2, …, fn) — e.g. Pacman location, ghost distances, food distance, or even raw screen pixels. A parameterized approximator v̂(s;θ) combines these features using tunable weights θ:

Linear approximator v̂(s;θ) = Σi θi fi(s)   — simplest case; more expressive forms (products, deep nets) also possible

A small neural network is the same idea stacked in layers: input features → hidden layer 1 (weights θ1–12) → hidden layer 2 (weights θ13–28) → output v̂ (weights θ29–32). Either way, the question that drives the rest of this session is: given we know the true value of a handful of states, how do we adjust θ to match them — and have that generalize?

Research Enhanced

The "curse of dimensionality" is the formal name for why tabular RL can't scale — the number of possible states grows exponentially with the number of state variables. The classic large-scale demonstration is Gerald Tesauro's TD-Gammon (1992), which used a small neural net to approximate backgammon state values instead of a table (backgammon has roughly 1020 states) and reached human-expert-level play. DeepMind's 2015 Atari DQN made the same bet at a much larger scale, using CNNs directly on raw pixels because there is no feasible tabular representation of "all possible pixel screens."

Sources: en.wikipedia.org/wiki/TD-Gammon · nature.com/articles/nature14236

Q. Why can't a Pacman agent just use a lookup table of state values?

Because the number of distinct Pacman board configurations (ghost positions × Pacman position × remaining food layout) is astronomically large — the agent could never visit, let alone store, a row for every one.

A table needs one entry per state; Pacman has far too many states to enumerate or store.

Key insight: generalization exists precisely because enumeration is infeasible.

Q. In the linear approximator v̂(s;θ)=Σθifi(s), what does "generalization" concretely mean once θ is tuned on one state?

  1. θ is a shared set of weights, not tied to any one state.
  2. Any new state S′ — seen or unseen — is evaluated by the exact same formula, using its own feature vector f(S′).
Tuning θ on state S automatically changes the predicted value for every other state that shares similar feature values with S — that sharing is generalization.

Key insight: features, not raw state identity, are what generalization is computed over.

Q. The deck reports naïve tabular Q-learning scoring −14 after 50 episodes vs. +19 with function approximation after the same 50 episodes. Explain the mechanism behind this gap.

  1. Tabular Q-learning treats any pixel-different configuration as an unrelated state with its own (initially zero) value.
  2. 50 episodes visit only a tiny fraction of all possible configurations, so most states the agent encounters late in an episode are still "unlearned," even if very similar dangerous states were visited earlier.
  3. A function approximator maps every state through shared features (e.g. "distance to nearest ghost"), so one dangerous encounter updates the value estimate for every state with a similar ghost-distance feature — including states never directly visited.
The identical training budget (50 episodes) yields wildly different performance because function approximation converts each single experience into knowledge about a whole neighborhood of states, while the table converts it into knowledge about exactly one state.

Key insight: sample efficiency, not just raw training volume, is the real payoff of generalization.

Exam Alert

Likely question: "Why does reinforcement learning need function approximation for real-world problems?" — cite the state-space explosion argument and the Pacman before/after scores as evidence.

Common mistake: saying tabular methods are "wrong" — they're correct but computationally infeasible at scale, which is a different claim.

Loss, Gradient Descent & the Learning Rate LAB

Intuition first

The deck poses the motivating problem concretely: suppose we already know the true value of a handful of states — say v(S1)=5, v(S2)=8, v(S3)=2 — and we want to set θ so that v̂(s;θ) matches these as closely as possible. We can't usually make θ fit every true value exactly — there are typically far more states than parameters, so a perfect fit is impossible (like trying to draw one straight line through ten randomly scattered points). Instead we minimize total error across the states we know about.

The first instinct — use absolute error — turns out to be a dead end: |v(s) − v̂(s;θ)| has a sharp kink at zero, so it isn't differentiable there, and gradient descent needs a smooth slope to follow. The deck's own phrasing: "Ooops! Absolute value is not differentiable → can't compute gradients." The fix is the classic one — square the error instead.

Squared value error (loss) loss = ½ Σs [ v(s) − v̂(s;θ) ]²

Gradient descent

For every parameter θi, the partial derivative ∂loss/∂θi tells you the direction that increases loss the most — so you step the opposite way:

Update rule θ ← θ − α ∇loss   where   ∇loss = ( ∂loss/∂θ1, ∂loss/∂θ2, …, ∂loss/∂θn )

Think of it as being blindfolded on a hilly landscape, feeling which way is downhill, and taking a step in that direction. The learning rate α controls step size: too large and you overshoot the valley, bouncing between hillsides forever (divergence); too small and you crawl toward the minimum, or get stuck prematurely in a shallow dip.

α settingEffect
Too largeOvershoots the minimum → oscillates or diverges entirely
Too smallConverges, but painfully slowly; may look "stuck" prematurely
Well-tunedSteady descent into the loss valley within a reasonable number of steps

Q. Why is squared error preferred over absolute error as a loss function here?

Absolute value has a non-differentiable kink at zero; squared error is smooth everywhere, so its gradient can always be computed.

Squared error is differentiable everywhere; absolute error is not differentiable at zero.

Key insight: squaring also penalizes large errors more heavily than small ones — a useful side-effect, not just a differentiability fix.

Q. What happens during gradient descent if the learning rate α is set far too large for the loss landscape?

  1. Each step moves further than the local slope actually justifies.
  2. The parameter overshoots the minimum and lands on the opposite side of the valley, often at a higher loss than before.
  3. Repeating this bounces the parameter back and forth with growing amplitude.
The updates diverge instead of converging — loss can grow without bound rather than shrink.

Key insight: "too large α" is a real failure mode, not just "slower convergence" — it can actively destroy training.

Q. Derive why the gradient of a linear approximator v̂(s;θ)=Σθifi(s) with respect to θ is simply the feature vector f(s) itself.

  1. v̂(s;θ) = θ1f1(s) + θ2f2(s) + … + θnfn(s).
  2. ∂v̂/∂θi = fi(s), since every other term in the sum doesn't involve θi and differentiates to 0.
  3. Stacking all partials gives ∇θv̂(s;θ) = ( f1(s), f2(s), …, fn(s) ) = f(s).
∇v̂(s;θ) = f(s) for a linear approximator — this is exactly why every worked weight-update example in this guide multiplies the TD/MC error by the feature vector.

Key insight: this shortcut only holds because the approximator is linear in θ; for a neural network the gradient must be computed via backpropagation instead.

Exam Alert

Likely question: derive or state the squared-error loss and the gradient-descent update rule; explain the consequence of a badly chosen learning rate.

Exam-critical: ∇v̂(s;θ) = f(s) for linear approximators — nearly every subsequent worked example in this course relies on this being second nature.

Gradient Monte Carlo Estimation LAB

Intuition first

Gradient Monte Carlo plays a full episode start-to-finish, then updates θ toward the actual observed return Gt — a real, honest measurement of "how good was this state, in hindsight." Because Gt is unbiased (correct on average), this method is guaranteed to converge to a local optimum. The catch: you must wait until the whole episode ends before you can compute Gt, so it can't learn "on the fly" during long or never-ending tasks.

Gradient Monte Carlo Algorithm for Estimating v̂ ≈ v_π

Input: the policy π to be evaluated
Input: a differentiable function v̂ : S × ℝ^d → ℝ

Initialize value-function weights w arbitrarily (e.g., w = 0)
Repeat forever:
    Generate an episode S0, A0, R1, S1, A1, …, RT, ST using π
    For t = 0, 1, …, T − 1:
        w ← w + α[Gt − v̂(St, w)] ∇v̂(St, w)

Worked example — Pacman feature vector

State S has features [2,2,1] (f1,2 = distance to ghost 1,2; f3 = distance to food). Weights start at θ = [0,0,0], and a full episode gives an observed return Gt = 10.

Update θ = [0,0,0] + 0.1 · (10 − [0,0,0]·[2,2,1]) · [2,2,1] = [0,0,0] + 0.1·10·[2,2,1] = [2,2,1]

Now predict a brand-new state S′ with features [2,4,1] — never directly visited — just by plugging into the same formula:

Prediction on an unseen state v̂(S′) = f(S′)·θ = [2,4,1]·[2,2,1] = (2×2)+(4×2)+(1×1) = 4+8+1 = 13

No table lookup needed for S′ — the linear formula instantly gives a sensible estimate purely because S′ shares similar features with the state we trained on.

Key Insight

The gradient of a linear v̂ with respect to θ is just the feature vector itself — that's why every update multiplies (error) × (features) directly, with no extra derivative machinery needed.

// 04

Semi-Gradient TD(0) & n-Step Returns LAB

Intuition first — bootstrapping without waiting for the episode to end

Monte Carlo needs a full episode before it can learn. Bootstrapping fixes this by updating using a guess of a guess: instead of the true final return Gt, use "immediate reward + our own current estimate of the next state's value." This lets the agent learn after every single step — much faster, and usable on tasks that never terminate.

Tabular TD(0) v̂(st) ← v̂(st) + α( rt + γ v̂(st+1) − v̂(st) )
Approximation TD(0) — "semi-gradient" θ ← θ + α( rt + γ v̂(st+1;θ) − v̂(st;θ) ) ∇v̂(st;θ)

Because we're using our own imperfect estimate as part of the target — bootstrapping ourselves up by our own bootstraps — the math isn't perfectly "clean": we only differentiate through the current prediction, not through the bootstrapped target itself. That's why it's called semi-gradient. This means it loses the formal convergence guarantee Monte Carlo has — but in practice it's usually faster and more broadly useful, especially with linear approximators.

Despite giving up the clean convergence guarantee, the deck is explicit that semi-gradient methods are often clearly preferred, for four reasons:

  • They converge reliably in important cases — notably the linear approximation case used throughout this course.
  • They typically enable significantly faster learning than full-gradient Monte Carlo methods.
  • They enable learning to be continual and online, without waiting for the end of an episode.
  • This makes them usable on continuing (non-episodic) problems and gives real computational advantages over storing a full episode before learning.
PropertyMonte CarloSemi-gradient TD
Needs full episode?YesNo — updates every step
Target is unbiased?Yes (Gt is real)No — bootstrapped, biased
Convergence guaranteeTo a local optimumReliable for linear case; not guaranteed in general
Works on continuing tasks?NoYes

Worked example

State S has features [2,3,1]; taking an action gives reward R=+10 and lands in S′ with features [1,2,1]. θ starts at [0,0,0].

Update θ = [0,0,0] + 0.1·(10 + [1,2,1]·[0,0,0] − [2,3,1]·[0,0,0])·[2,3,1] = [2,3,1]

Predicting a brand-new state U with features [2,4,1]:

Prediction v̂(U) = [2,4,1]·[2,3,1] = (2×2)+(4×3)+(1×1) = 4+12+1 = 17

n-step returns — the middle ground

n-step TD sits between one-step TD (bootstrap almost immediately) and Monte Carlo (bootstrap never). Bigger n means more real observed reward (less bias) but more randomness in the trajectory (more variance) — the classic bias–variance tradeoff.

This spectrum is the classic "backup diagram" from Sutton & Barto Ch.7: each rung is a chain of real-experience steps (drawn as filled dots) terminating in a bootstrapped estimate (an open circle) — 1-step TD bottoms out after one real reward, Monte Carlo never bottoms out until the actual terminal state. The tabular version of this algorithm updates a table entry V(Sτ) directly; the n-step semi-gradient version below is the one-line generalization to weight updates.

n-step semi-gradient TD for estimating v̂ ≈ v_π

Initialize value-function weights w arbitrarily (e.g., w = 0)
Repeat (for each episode):
    Initialize and store S0 ≠ terminal
    T ← ∞
    For t = 0, 1, 2, …:
        If t < T, then:
            Take an action according to π(·|St)
            Observe/store next reward Rt+1 and next state St+1
            If St+1 is terminal, then T ← t+1
        τ ← t − n + 1     (τ is the time whose estimate is updated)
        If τ ≥ 0:
            G ← Σ γ^(i−τ−1) Ri  for i = τ+1 … min(τ+n, T)
            If τ+n < T: G ← G + γ^n v̂(S_(τ+n), w)
            w ← w + α[G − v̂(Sτ,w)] ∇v̂(Sτ,w)
    Until τ = T − 1

Notice the only real change from the tabular n-step algorithm: a weight update (w ← w + α[G − v̂(Sτ,w)]∇v̂(Sτ,w)) instead of a tabular entry update — the n-step bookkeeping logic is otherwise identical.

Research Enhanced

The instability of bootstrapped methods combined with function approximation and off-policy training is formalized as "the deadly triad" in Sutton & Barto's textbook. A famous illustration is Baird's counterexample (1995) — a simple 7-state MDP where semi-gradient TD with linear function approximation provably diverges, even though the tabular version converges fine. This is one reason DQN needed extra stabilizers (target networks, experience replay) — see Section 08.

Sources: incompleteideas.net/book/RLbook2020.pdf (§11.3, "Deadly Triad")

Q. What is the main practical advantage of semi-gradient TD(0) over Gradient Monte Carlo?

It updates after every single step rather than waiting for an episode to finish, so it works on long or never-ending tasks and typically learns faster.

Online, step-by-step learning — no need to wait for episode termination.

Key insight: the tradeoff is losing the formal convergence guarantee that Monte Carlo methods have.

Q. θ=[1,1,1], features f(S)=[1,0,1], reward R=4, γ=0.5, α=0.2, and v̂(S′;θ)=3. Compute the new θ using semi-gradient TD(0).

  1. v̂(S;θ) = [1,0,1]·[1,1,1] = 1+0+1 = 2.
  2. TD error = R + γv̂(S′;θ) − v̂(S;θ) = 4 + 0.5(3) − 2 = 4+1.5−2 = 3.5.
  3. θ ← θ + α·error·f(S) = [1,1,1] + 0.2×3.5×[1,0,1] = [1,1,1] + [0.7,0,0.7].
New θ = [1.7, 1, 1.7].

Key insight: only the weights tied to non-zero features actually change on this update — the middle weight (tied to a zero feature) stays untouched.

Q. Explain, in terms of bias and variance, why n-step returns with a moderate n often outperform both 1-step TD and full Monte Carlo in practice.

  1. 1-step TD bootstraps almost immediately — low variance (only one random reward involved) but high bias, since it leans heavily on a possibly-inaccurate current value estimate.
  2. Monte Carlo uses zero bootstrapping — unbiased target, but high variance, since the full trajectory of rewards is random and can swing widely between episodes.
  3. An intermediate n uses n real rewards (reducing reliance on the current, possibly-wrong estimate — lower bias than 1-step) while still bootstrapping the tail (capping variance growth compared to full Monte Carlo).
n-step returns occupy a tunable "sweet spot" on the bias–variance curve; this is exactly why multi-step returns are one of the independently-verified performance boosts in DeepMind's Rainbow DQN paper.

Key insight: there's no free lunch — you're choosing where on the bias–variance spectrum to sit, not eliminating the tradeoff.

Exam Alert

Likely question: compute a semi-gradient TD(0) weight update given θ, features, reward, and next-state features; explain why semi-gradient methods aren't guaranteed to converge in general.

Common mistake: forgetting to bootstrap through the next state's value with the current θ — students sometimes compute the TD error as if this were Monte Carlo (using an actual return Gt instead of r + γv̂(s′)).

// 05

Feature Construction: Polynomial, Fourier, Coarse & Tile Coding

Intuition first — the hardest remaining question

Once you've decided to use a linear approximator v̂(f(s);θ) = f(s)·θ, the hardest remaining question is: what numbers should represent the state? For Pacman, maybe "distance to nearest ghost." For a racing game, maybe "speed." For Breakout, maybe "ball position and velocity." The problem: hand-designing features for every new domain requires a domain expert — it doesn't scale to a general-purpose agent that should play any game without human help.

Raw pixel data doesn't hand you these concepts directly — a pixel is just pixel(7,3) = [0,0,0] (black); you want "where's the ball," "how fast is it moving," which must be inferred, not read off. The rest of this section is a tour of ways to automatically construct features — polynomial and Fourier bases (global, mathematically-defined), coarse and tile coding (local, region-based) — ending with the observation that all of them are still, ultimately, a "needle in a combinatorial haystack" compared to what a deep neural network can learn automatically.

Polynomial and Fourier bases

Polynomial basis fi(s) = Πj=1..k xjci,j   where each ci,j ∈ {0,1,…,n} → (n+1)k total features
Fourier basis fi(s) = cos( π X⊤ ci )   — cosine waves of different frequencies over the state dimensions

Polynomials generate combinations like x1, x2, x1², x1x2, etc. — this lets a "linear" approximator fit curved relationships, since even though the weights combine linearly, the inputs are nonlinear transforms. The Fourier basis instead decomposes the value function into cosine components, just like decomposing a sound wave into pure tones — higher-frequency terms capture fine "wiggly" detail; lower-frequency terms capture broad trends. Both suffer the same curse of dimensionality: (n+1)k features explodes exponentially as state dimensions grow.

Coarse coding

Represent a continuous state as being "inside" or "outside" many overlapping regions (e.g. circles). If a state falls inside a circle, that feature turns on (1); otherwise it's off (0). Overlapping circles mean nearby states share many active features — updating one circle's weight automatically shifts the value estimate for every other state that also falls in that circle.

State s inside circles A, B, C
features: 1,1,1,0,0…
↔
Nearby state s′ inside B, C, D
features: 0,1,1,1,0…
Circle sizeEffect
Narrow generalizationPrecise but slow to spread useful info; sharp final detail
Broad generalizationFast to spread info; blurrier/less-precise final detail
AsymmetricStretched circles bias generalization more strongly along one state dimension

The deck's own training-curve chart makes this concrete: approximating a "box" target function (flat, with a raised rectangular bump), tracked at 10, 40, 160, 640, 2560, and 10,240 training examples. With narrow features, early estimates (10 examples) look jagged and slow to generalize, but eventually trace the box's sharp edges accurately. With broad features, early estimates already look like a smooth wide bump (fast generalization), but the final approximation stays rounded/blurred at the edges rather than sharp. Medium-width features sit in between. This is the same bias–variance-style tradeoff from Section 04, now expressed as a resolution-vs-generalization-speed tradeoff.

Tile coding

A computationally efficient special case of coarse coding: lay multiple grids ("tilings") over the state space, each offset slightly from the others. Any point activates exactly one tile per tiling — so with 4 tilings, exactly 4 out of thousands of possible tile-features turn on. This sparsity makes updates fast, while offset overlap still gives smooth generalization.

Key Insight

Empirically, more overlapping tilings converge faster: on the deck's own chart, "50 tilings" reaches lower root-value-error much faster than "state aggregation (one tiling)" over 5,000 episodes. Tile shapes needn't be plain squares either — irregular, log-spaced, or diagonal tilings all make sense depending on which combinations of state variables matter most.

Research Enhanced

Tile coding traces back to Albus's CMAC (Cerebellar Model Arithmetic Computer, 1975), a biologically-inspired cerebellar learning model, later refined for RL by Rich Sutton. It has been used extensively in robotics (Tham 1994, Q-learning/Sarsa(λ) for robot control) and classic RL benchmarks like Mountain Car and RoboCup soccer (Stone & Sutton, 2001), precisely because it handles continuous, multi-dimensional state spaces without the exponential blow-up of a naïve polynomial basis. The Fourier basis for RL was separately formalized by Konidaris, Osentoski & Thomas (2011), who showed it often outperforms both polynomial and radial basis functions on classic control tasks while needing fewer free parameters.

Sources: medium.com/criteo-engineering — tile coding · incompleteideas.net/tiles · arxiv.org/abs/1109.4991 (Fourier basis)

The pivot: why deep learning takes over from here

All the hand-designed feature methods above share a weakness: they require guessing a reasonable structure in advance, and for high-dimensional raw inputs like pixels, the "right" features might technically exist mathematically but are effectively impossible to find by hand — a needle in a combinatorially huge haystack. The proposed fix, which the rest of this course (Sections 06–08) builds toward: let a deep neural network learn the features automatically through training. This is exactly what CNNs do for pixel-based Atari games in Deep Q-Networks.

Q. In tile coding with 5 offset tilings, how many tile-features are active for any given state?

Exactly 5 — one active tile per tiling, regardless of how many total tiles exist across all tilings.

Exactly one active tile per tiling → 5 active features total.

Key insight: this "one-hot per tiling" structure is what keeps tile coding sparse and cheap to update.

Q. Why does both the polynomial basis and the Fourier basis suffer from the curse of dimensionality?

  1. Both generate one feature for every combination of per-dimension "degrees" or "frequencies" up to order n.
  2. With k state dimensions, the number of such combinations is (n+1)k.
The feature count grows exponentially in k (the number of state dimensions), so both bases become impractical once the state has more than a handful of dimensions.

Key insight: this is exactly why coarse/tile coding (local, sparse) or deep learning (learned, not enumerated) are preferred for high-dimensional states.

Q. Contrast coarse coding's "narrow vs. broad" circle-size tradeoff with tile coding's "number of tilings" tradeoff — are they the same knob?

  1. In coarse coding, circle size controls generalization width per feature: bigger circles → faster spread of learning but blurrier final resolution.
  2. In tile coding, the analogous "size" knob is the tile width within a single tiling — larger tiles behave like larger coarse-coding circles.
  3. But tile coding adds an independent second knob: number of tilings. More tilings (each offset slightly) increases resolution and smoothness without shrinking any individual tile — this is not available in single-layer coarse coding.
Tile width is analogous to coarse-coding circle size, but the number of overlapping tilings is a genuinely separate axis that lets tile coding get both broad reach and fine resolution simultaneously — which is why 50 tilings clearly outperforms one tiling ("state aggregation") on the deck's own convergence chart.

Key insight: tile coding is coarse coding plus a structured, computationally cheap way to add many overlapping "layers" of resolution.

Exam Alert

Likely question: compare/contrast polynomial basis, Fourier basis, coarse coding, and tile coding — feature representation, dimensionality scaling, and generalization behavior.

Exam-critical: know that tile coding activates exactly one tile per tiling, and that coarse-coding circle size trades off generalization speed against final precision.

On-Policy vs Off-Policy: SARSA vs Q-Learning LAB

Intuition first — the Chrome T-Rex Dino game

The second deck runs this entire comparison through the offline Chrome "No Internet" T-Rex game: state space larger in dimension (obstacle distance, height, speed), action space {0 – No-Op, 1 – Jump, 2 – Duck}. The deck poses a direct tradeoff:

RequirementChoice
Sample-efficient learning with fast convergenceOff-policy — Q-learning
Online, stable learningOn-policy — SARSA

Feature construction for the Dino game (coarse coding, applied)

Before values can be approximated, the continuous Dino state needs features — the deck applies coarse coding from Section 05 directly: two overlapping circular feature detectors, F1 and F2, laid over a 2D space of distance to the first obstacle (x-axis) and height of the first obstacle (y-axis).

State S1
inside circle F1 only
φ(1,0)
↔
State S2
inside F1 and F2 overlap
φ(1,1)

S1 falls only inside F1, giving encoding φ(1,0). S2 falls inside both circles' overlap region, giving φ(1,1). This is exactly coarse coding from Section 05, now applied concretely to a game state.

Encoding the action into the feature vector

Since we're now estimating action values Q(s,a) instead of state values V(s), the action must be part of the feature vector, or the same features would give the same value regardless of which action is being considered. The deck's trick: append the action as an extra number onto the state's feature vector.

Feature encoding S1: φ(1,0,0) if no action performed  ·  S2: φ(1,1,0) if no action performed  ·  S3: φ(1,1,1) if "jump" action performed

Semi-gradient SARSA (on-policy)

Episodic Semi-gradient Sarsa for Estimating q̂ ≈ q*

Initialize value-function weights w arbitrarily (e.g., w = 0)
Loop for each episode:
    S, A ← initial state and action (e.g., ε-greedy)
    Loop for each step of episode:
        Take action A, observe R, S′
        If S′ is terminal:
            w ← w + α[R − q̂(S,A,w)] ∇q̂(S,A,w)
            Go to next episode
        Choose A′ as a function of q̂(S′,·,w) (e.g., ε-greedy)
        w ← w + α[R + γ q̂(S′,A′,w) − q̂(S,A,w)] ∇q̂(S,A,w)
        S ← S′;  A ← A′

SARSA's target uses q̂(S′,A′,w) — the value of the actual next action A′ that will really be taken, chosen the same (e.g. ε-greedy) way every action is chosen. That's what makes it on-policy: it evaluates the same policy it's actually following, exploration and all.

Semi-gradient Q-learning (off-policy)

Q-learning (off-policy TD control) for estimating π ≈ π*

Repeat (for each episode):
    Initialize S
    Repeat (for each step of episode):
        Choose A from S using policy derived from Q (e.g., ε-greedy)
        Take action A, observe R, S′
        θ = θ + α( R + γ max_a Q̂(S′,a;θ) − Q̂(S,A;θ) ) ∇θ Q̂(S,A;θ)
        S ← S′
    until S is terminal

Q-learning's target uses maxa Q̂(S′,a;θ) — the value of the best possible next action, regardless of what the agent will actually do. That's what makes it off-policy: it learns about the greedy/optimal policy's values even while the agent may be behaving more randomly (exploring) during training.

Worked numeric comparison — T-Rex Dino transition

Setup: θ=[1.0,0.5,1.0], γ=0.2, α=0.9. Transition: (S1, action:0, reward:2, S2, next action:0). S1: φ(1,0,0), S2: φ(1,1,0). Current estimate Q(S1,a=0,θ) = [1,0,0]·[1.0,0.5,1.0] = 1.0.

SARSA target (uses actual next action = 0) error = r + γQ(s2′,a′=0,θ) − Q(s1,a=0,θ) = 2 + 0.2([1,1,0]·[1.0,0.5,1.0]) − 1.0 = 2 + 0.2(1.5) − 1.0 = 2.3 − 1.0 = 1.3
Q-learning target (uses MAX over both next actions) error = r + γ·MAX{ Q(s2′,0,θ), Q(s2′,1,θ) } − Q(s1,a=0,θ) = 2 + 0.2·MAX{1.5, 2.5} − 1.0 = 2 + 0.2(2.5) − 1.0 = 2.5 − 1.0 = 1.5

Applying the SGD update (θ ← θ + α·error·[1,0,0], since only the first feature is active):

MethodErrorUpdated θ1
SARSA (on-policy)1.31.0 + 0.9×1.3 = 2.17
Q-learning (off-policy)1.51.0 + 0.9×1.5 = 2.35

Because Q-learning's error (1.5) is larger than SARSA's (1.3), its weight update is also larger — it pushes its estimate up further, purely by assuming the best-case next action will be taken. This "optimism" is exactly what causes the maximization bias covered in Section 07.

Q. Which method — SARSA or Q-learning — is on-policy, and what's the one-line reason?

SARSA is on-policy because its target uses the value of the action the policy will actually take next (A′), including exploration.

SARSA is on-policy; Q-learning is off-policy because it always targets the max over next actions, regardless of what will actually be done.

Key insight: "on-policy" means evaluating the policy you're actually following; "off-policy" means evaluating a different (typically greedy) policy.

Q. In the T-Rex worked example, why is the Q-learning error (1.5) larger than the SARSA error (1.3) for the identical transition?

  1. Both start from the same current estimate Q(S1,a=0,θ)=1.0 and the same reward, γ, and S2.
  2. SARSA's target uses Q(S2, a′=0) = 1.5 (the actual next action taken).
  3. Q-learning's target uses MAX{Q(S2,0), Q(S2,1)} = MAX{1.5, 2.5} = 2.5 — the best possible action, not the one actually taken.
Q-learning substitutes the higher-valued hypothetical action (2.5) for the actually-taken action's value (1.5), producing a bigger target and hence a bigger TD error.

Key insight: Q-learning is intrinsically "optimistic" about what happens next — useful for fast convergence, risky for bias (see Section 07).

Q. Suppose the actual next action taken in the SARSA experience tuple had instead been action 1 (not action 0). Would SARSA's target now equal Q-learning's target? Explain.

  1. SARSA's target would become r + γQ(S2,a′=1,θ) = 2 + 0.2(2.5) = 2.5.
  2. Q-learning's target is always r + γ·MAX{Q(S2,0),Q(S2,1)} = 2 + 0.2(2.5) = 2.5, regardless of which action SARSA's tuple recorded.
  3. So yes — in this specific case the two coincide, because the actually-taken action A′=1 happens to be the same one that maximizes Q(S2,·).
SARSA and Q-learning only diverge when the actually-taken next action is not the greedy/maximizing one — e.g. under ε-greedy exploration, when a random (non-greedy) action gets taken. When the policy behaves greedily, the two targets coincide exactly.

Key insight: the on-policy/off-policy distinction only matters in the presence of exploration — a purely greedy policy makes SARSA and Q-learning identical.

Common mistake: using the max over next actions for SARSA (that's Q-learning), or using the specific next action taken for Q-learning (that's SARSA) — the whole point of this section is that they use different next-state action selections.

Maximization Bias & Double Q-Learning LAB

Intuition first — why MAX is dangerous

Suppose the true value of both actions at state S2 is actually equal — say 2.0 each. But our function approximator, still training, gives noisy estimates: action 0 comes out as 1.5 (underestimate), action 1 comes out as 2.5 (overestimate) — purely due to noise, not because action 1 is genuinely better.

Q-learning's MAX operator will always pick whichever estimate happens to be highest — here, 2.5 — even though that's an artifact of noise. Statistically, taking the maximum over several noisy estimates of similar true values systematically overestimates the true maximum, on average. This is called maximization bias.

Key Insight

Given true values Q(S2,0)=Q(S2,1)=2.0, and noisy estimates Q(S2,0)=1.5, Q(S2,1)=2.5: the correct expected target should be around 2 + 0.2×2.0 = 2.4. But vanilla Q-learning's target is 2 + 0.2×2.5 = 2.5 — inflated purely by picking whichever noisy estimate happened to be lucky.

The fix: decouple selection from evaluation

Use two independent value estimates — one (θ) to decide which action looks best, and a separate, independently-trained one (θ′) to evaluate how good that chosen action actually is. Since θ′ wasn't involved in "cherry-picking" the best-looking action, it's much less likely to share the same lucky noise.

(Tabular) Double Q-learning, for estimating Q1 ≈ Q2 ≈ q*

Initialize Q1(s,a) and Q2(s,a) for all s,a, such that Q(terminal,·) = 0
Loop for each episode:
    Initialize S
    Loop for each step of episode:
        Choose A from S using ε-greedy in Q1 + Q2
        Take action A, observe R, S′
        With 0.5 probability:
            Q1(S,A) ← Q1(S,A) + α( R + γQ2(S′, argmax_a Q1(S′,a)) − Q1(S,A) )
        else:
            Q2(S,A) ← Q2(S,A) + α( R + γQ1(S′, argmax_a Q2(S′,a)) − Q2(S,A) )
        S ← S′
    until S is terminal

Worked example — Double Q-learning on the T-Rex transition

Same setup as Section 06: θ=[1.0,0.5,1.0], θ′=[0.1,0.3,1.0]. True value Q(S2,0)=Q(S2,1)=2.0.

Step 1 — select the action using θ ARGMAX{ Q(s2′,0,θ), Q(s2′,1,θ) } = ARGMAX{1.5, 2.5} → action a1
Step 2 — evaluate that selected action using the SEPARATE θ′ Q(s2′, a1, θ′) = [1,1,1]·[0.1,0.3,1.0] = 0.1+0.3+1.0 = 1.4

Notice: 1.4 is much lower than what θ alone said for action 1 (2.5) — because θ′ wasn't involved in cherry-picking which action looked best.

Double-Q target and error target = 2 + 0.2(1.4) = 2.28 → error = 2.28 − 1.0 = 1.28

Research Enhanced

Maximization bias was first formally identified by Thrun & Schwartz (1993) and rigorously analyzed and solved by Hado van Hasselt in his 2010 NeurIPS paper, "Double Q-learning." Van Hasselt later extended the fix to deep learning with Double DQN (2016, AAAI), shown to substantially improve performance across many Atari games — because Atari environments and neural-network function approximation are especially prone to producing noisy Q-value estimates that trigger this exact bias.

Sources: proceedings.neurips.cc — Double Q-learning · arxiv.org/abs/2210.05262

Q. In one sentence, what causes maximization bias?

Taking the MAX over several noisy estimates of similar (or equal) true values systematically overestimates the true maximum.

The MAX operator preferentially selects whichever estimate got lucky noise, not necessarily the genuinely best action.

Key insight: more noise in your value estimates → worse overestimation, since MAX has more "lucky outliers" to choose from.

Q. Why does Double Q-learning use a different weight vector to evaluate the chosen action than the one used to select it?

  1. If the same weights (θ) were used for both selection and evaluation, whatever noise inflated an action's estimate enough to be selected would also inflate the number used to evaluate it.
  2. Using an independent θ′ (trained on different data/noise) for evaluation means that inflated noise is unlikely to also appear in θ′'s estimate of that same action.
Decoupling selection (θ) from evaluation (θ′) breaks the correlation between "why an action was picked" and "how good it's judged to be" — removing the systematic upward bias.

Key insight: this is why the T-Rex Double-Q evaluation (1.4) is much lower than the same action's value under θ alone (2.5).

Q. Double Q-learning is known to sometimes underestimate true values rather than overestimate them. Explain why this happens, and why it's considered a less damaging failure mode.

  1. Because θ and θ′ are each trained on only a portion of experience (or independently), each individually still carries its own estimation noise.
  2. Using θ to select the action and θ′ (a differently-noised estimator) to evaluate it means the evaluation is no longer selectively picking out inflated values — but it can occasionally pick out a deflated one instead, since θ′'s noise for the selected action is essentially independent of whether that action looked good under θ.
  3. On average, this process removes the systematic upward pull of the MAX operator, but doesn't introduce a new systematic pull in either direction — so any resulting bias tends to be smaller and less consistent than the guaranteed overestimation of vanilla Q-learning.
A mild, inconsistent underestimation is far less damaging than plain Q-learning's guaranteed, exploitable overestimation — because overestimated actions get "over-trusted" and repeatedly chosen (compounding the error), whereas underestimated actions are merely under-explored, a milder and self-correcting failure mode.

Key insight: van Hasselt's own analysis shows Double Q-learning trades guaranteed overestimation for occasional, smaller underestimation — a favorable trade in practice.

Likely question: given noisy Q-estimates under θ and a separate θ′, work through the full Double Q-learning target/error/update, and compare it to the plain Q-learning result on the same numbers.

Exam-critical: know the two-step mechanic by heart — select the action via ARGMAX under one estimator, evaluate it using the other.

Deep Q-Networks: Experience Replay & Target Networks

Intuition first — why the T-Rex approach breaks down at scale

Every consecutive sequence of states in a real video game is highly correlated — frame t looks almost identical to frame t+1. Training a neural network on these highly correlated, sequential samples (especially combined with off-policy bootstrapping — recall the "deadly triad" from Section 04) can make training unstable and cause divergence. Deep Q-Networks (DQN) solve this with two signature tricks: experience replay and a target network.

The DQN loss

Loss function (Mnih et al., 2015) Li(θi) = 𝔼s,a[ (yi − Q̂(s,a;θi))² ]    where   yi = r + γ maxa′ Q̂(s′,a′;θi−1)

Crucially, yi is treated as a constant during this gradient computation — we only differentiate through the current prediction Q̂(s,a;θi), never through the bootstrapped target itself. This is the same "semi-gradient" trick from Section 04, now applied inside a neural network.

Full algorithm — Q-learning with experience replay

Q-learning with experience replay (Mnih et al., 2015)

Initialize replay memory D to capacity N
Initialize action-value function Q with random weights θ
Initialize target action-value function Q̂ with weights θ⁻ = θ
For episode = 1, M do                                // play M full games
    Initialize s1 = {x1}, preprocess φ1 = φ(s1)       // 4-frame stack, grayscale, downsample, crop
    For t = 1, T do
        With prob ε select a random action at          // explore
        otherwise select at = argmax_a Q(φ(st),a;θ)     // exploit
        Execute at, observe reward rt and image x_(t+1)
        Set s_(t+1) = st,at,x_(t+1); preprocess φ_(t+1)
        Store transition (φt,at,rt,φ_(t+1)) in D
        Sample random minibatch (φj,aj,rj,φ_(j+1)) from D
        Set yj = rj                                          if episode terminates at j+1
              yj = rj + γ max_a′ Q̂(φ_(j+1),a′;θ⁻)              otherwise
        Gradient descent step on (yj − Q(φj,aj;θ))² w.r.t. θ  // online net ONLY, never θ⁻
        Every C steps: reset θ⁻ = θ                    // refresh target network
    End For
End For

Why the target network is essential

If you used the same, constantly-changing network to both predict and set its own target, improving the prediction for one state-action pair would immediately shift the target for many other states too — like chasing a moving target that runs away every time you get closer. The original Nature paper states this precisely:

From the Nature paper

"This modification makes the algorithm more stable compared to standard online Q-learning, where an update that increases Q(st,at) often also increases Q(st+1,a) for all a and hence also increases the target yj, possibly leading to oscillations or divergence of the policy." — Mnih et al., Human-level control through deep reinforcement learning, Nature 518.7540 (2015): 529.

Four consecutive frames are stacked so the network can perceive motion/velocity (essential for games like Pong or Breakout, where knowing which way the ball is moving matters), not just a static image.

Experience replay

DQN stores the last N experience tuples in a memory buffer (old transitions get overwritten, like a circular queue) and samples random, uniform mini-batches for training — breaking the harmful correlation between consecutive, near-identical game frames. The deck poses a natural improvement question: shouldn't more "important" or "surprising" transitions be replayed more often than routine ones? That leads directly to Prioritized Experience Replay.

Empirical DQN results

The deck reports the original paper's own evaluation protocol: each plotted point is the average score per episode after running the trained agent with an ε-greedy policy (ε = 0.05) for 520,000 frames, on SpaceInvaders and Seaquest. Over roughly 200 training epochs, both the average score-per-episode and the network's own average predicted Q-value (measured on a fixed held-out set of states) rise steadily, though noisily — direct evidence the network is learning useful policies and that its internal value estimates are behaving in a stable, non-divergent way, rather than the oscillation the target network is designed to prevent.

Research Enhanced

The original DQN paper, "Human-level control through deep reinforcement learning" (Mnih et al., Nature, 2015), was a landmark result: a single architecture and hyperparameter set (with per-game training) achieved human-level or superhuman performance on the majority of 49 different Atari 2600 games — learning directly from raw pixels and score, with no game-specific feature engineering at all. Prioritized Experience Replay (Schaul, Quan, Antonoglou & Silver, 2015) replaces uniform sampling with probability proportional to TD-error magnitude, and was one of six components combined in DeepMind's Rainbow DQN (2017) to substantially outperform vanilla DQN across the full Atari benchmark suite.

Sources: nature.com/articles/nature14236 · arxiv.org/abs/1511.05952 (Prioritized Experience Replay) · arxiv.org/abs/1710.02298 (Rainbow)

Q. What are the two signature stabilizing tricks introduced by DQN?

Experience replay (random mini-batches from a stored buffer) and a target network (a periodically-frozen copy of the network used to compute targets).

Experience replay + target network.

Key insight: both tricks exist to fix a different instability — replay fixes correlated samples, the target network fixes the "moving target" problem.

Q. Why does the gradient descent step in DQN's algorithm only update θ (the online network) and never θ⁻ (the target network)?

  1. θ⁻ is meant to stay fixed for many steps, so that the target yj it produces is stable while θ is trained toward it.
  2. If θ⁻ were updated by gradient descent too, it would chase its own output — reintroducing the moving-target instability the trick exists to prevent.
θ⁻ is only ever updated by direct copying (θ⁻ ← θ) every C steps — never by gradient descent — precisely to keep the target stable during those C steps.

Key insight: "target network" = frozen-by-design, refreshed only periodically and only by copying.

Q. Explain how experience replay and the "deadly triad" (Section 04) are connected — why does DQN specifically need replay, when tabular Q-learning didn't?

  1. The deadly triad names three ingredients that combine to threaten convergence: function approximation, bootstrapping, and off-policy learning.
  2. DQN has all three: a CNN (function approximation), a bootstrapped TD target (maxa′Q̂), and off-policy Q-learning updates.
  3. Feeding the network highly correlated, sequential frames (the raw order of gameplay) on top of this triad tends to make the moving, correlated updates compound and destabilize training even faster.
  4. Experience replay de-correlates the training stream by sampling randomly from a large buffer of past transitions — directly attacking the correlation problem, one of the compounding factors, even though it doesn't remove the underlying deadly-triad risk entirely (the target network handles a different part of that risk).
Tabular Q-learning has no function approximation at all (no shared parameters across states), so there's no "moving target" or generalization-driven instability to worry about — the deadly triad literally can't apply. DQN's use of a CNN makes all three legs of the triad present simultaneously, which is exactly why it needs both experience replay and a target network to remain stable in practice.

Key insight: experience replay and target networks are targeted fixes for specific instability mechanisms, not generic "best practices" — understanding which problem each solves is what the exam is really testing.

  • Reinforcement learning must generalize from observed experience if it is to be applicable to real-world domains (Section 01).

Conceptual Deep Dives

A · Bias–Variance and the n-step spectrum

Every method in Sections 03–04 sits somewhere on a spectrum from "trust the current estimate" (1-step TD: low variance, high bias) to "trust only what actually happened" (Monte Carlo: high variance, zero bias). n-step returns and eligibility traces (TD(λ), which blends all n-step returns with exponentially decaying weights) let you dial along this spectrum. Empirically, an intermediate n is often a genuine sweet spot — DeepMind's Rainbow DQN paper independently verified multi-step returns as one of several components that measurably improve performance over vanilla 1-step DQN.

B · The Deadly Triad

Function approximation + bootstrapping + off-policy learning, combined, can cause value estimates to diverge — this is Sutton & Barto's "deadly triad." Baird's counterexample (1995) is the classic proof-by-construction: a 7-state MDP where semi-gradient TD with linear approximation provably diverges. DQN contains all three legs of the triad (CNN function approximation, bootstrapped TD target, off-policy Q-learning) — which is exactly why it needed both a target network and experience replay to remain practically stable, even without a formal convergence guarantee.

C · Least-Squares TD (LSTD) vs. iterative SGD

For linear approximators specifically, Least-Squares TD (Bradtke & Barto, 1996; extended to LSTD(λ) by Boyan, 1999) solves directly for the fixed point of the linear TD update — rather than incrementally nudging weights with a learning rate. This is far more sample-efficient (uses every data point "fully") at the cost of higher per-step computational complexity (roughly O(d²)–O(d³) for d features, vs O(d) for SGD-based TD) — favored when real-world data is scarce or expensive (e.g. some robotics/healthcare RL), avoided in huge-feature deep RL settings where SGD dominates.

D · From hand-crafted features to learned features

Section 05's entire arc — polynomial basis → Fourier basis → coarse coding → tile coding — is a search for reasonable, human-designable feature structure. Deep Q-Networks sidestep the search entirely: the two convolutional layers in the DQN architecture learn feature detectors (edges, shapes, positions) directly from raw pixels via backpropagation, solving the "needle in a combinatorial haystack" problem raised at the end of Section 05 without any domain expertise at all.

E · Prioritized Experience Replay & Rainbow DQN

Vanilla experience replay (Section 08) samples uniformly at random. Prioritized Experience Replay (Schaul et al., 2015) instead samples proportional to TD-error magnitude — transitions the network is currently "most wrong" about get replayed more often — with importance-sampling weights added to correct the resulting gradient bias. This, combined with Double DQN and other tricks, is part of DeepMind's Rainbow DQN (2017), which combined 6 independent improvements to substantially outperform vanilla DQN across the Atari benchmark suite.

F · DQN preprocessing & target-network math, restated

Target computation using the FROZEN target network yj = rj + γ maxa′ Q̂(φj+1, a′; θ⁻)   — θ⁻ only changes by copying, every C steps

Practice Questions — Exam-Style

Six worked problems written to mirror typical exam weighting and phrasing for this chapter (value function approximation, SARSA vs Q-learning, maximization bias, DQN). These are original practice questions modeled on the material above, not reproductions of any specific past paper — use them as a closed-book mock.

Q1 [3M]. A linear approximator uses features f1=distance-to-ghost, f2=distance-to-food, f3=bias term (always 1). Weights are θ=[0.5, 1.5, −1]. For a state with f(s)=[3,2,1], compute v̂(s;θ). Then, for a new unseen state f(s′)=[1,4,1], compute v̂(s′;θ) and explain why no retraining was needed to evaluate s′.

  1. v̂(s;θ) = [3,2,1]·[0.5,1.5,−1] = 1.5+3−1 = 3.5.
  2. v̂(s′;θ) = [1,4,1]·[0.5,1.5,−1] = 0.5+6−1 = 5.5.
v̂(s)=3.5, v̂(s′)=5.5. No retraining was needed because the linear formula applies to any feature vector — generalization is "free" once θ is learned; it's a function evaluation, not a lookup.

Key insight: the whole point of function approximation is that prediction on unseen states is just plugging into the same formula.

Q2 [4M]. Using Gradient Monte Carlo, θ starts at [1,1], features f(S)=[2,1], and the observed return for the episode is Gt=6. With α=0.2, compute the new θ. Then predict v̂ for a new state f(S′)=[3,0] using the updated θ.

  1. v̂(S;θ) = [2,1]·[1,1] = 2+1 = 3.
  2. Error = Gt − v̂(S;θ) = 6 − 3 = 3.
  3. θ ← θ + α·error·f(S) = [1,1] + 0.2×3×[2,1] = [1,1] + [1.2, 0.6] = [2.2, 1.6].
  4. v̂(S′;θ) = [3,0]·[2.2,1.6] = 6.6 + 0 = 6.6.
Updated θ = [2.2, 1.6]; predicted v̂(S′) = 6.6.

Key insight: Gradient Monte Carlo's update is unbiased (Gt is the real return), so this single update is guaranteed, on average, to move θ toward a better fit.

Q3 [4M]. Using semi-gradient TD(0), θ=[0.5,0.5], f(S)=[1,2], f(S′)=[2,2], R=3, γ=0.9, α=0.1. Compute the TD error and the updated θ.

  1. v̂(S;θ) = [1,2]·[0.5,0.5] = 0.5+1 = 1.5.
  2. v̂(S′;θ) = [2,2]·[0.5,0.5] = 1+1 = 2.
  3. TD error = R + γv̂(S′;θ) − v̂(S;θ) = 3 + 0.9(2) − 1.5 = 3+1.8−1.5 = 3.3.
  4. θ ← θ + α·error·f(S) = [0.5,0.5] + 0.1×3.3×[1,2] = [0.5,0.5] + [0.33,0.66] = [0.83, 1.16].
TD error = 3.3; updated θ = [0.83, 1.16].

Key insight: notice v̂(S′;θ) was computed using the current (pre-update) θ — that's the bootstrapping step, and it's what makes this a "semi"-gradient rather than a full-gradient method.

Q4 [5M]. θ=[2.0, 1.0, 0.5], γ=0.5, α=0.5. Transition: (S1, action:0, reward:4, S2, next action taken:1). S1 features: φ(1,0,0). S2 features under action 0: φ(1,1,0); under action 1: φ(1,1,1). (a) Compute both the SARSA target/error and the Q-learning target/error. (b) Update θ1 for each method and comment on which is more "optimistic."

  1. Q(S1,a=0,θ) = [1,0,0]·[2.0,1.0,0.5] = 2.0.
  2. Q(S2,a=0,θ) = [1,1,0]·[2.0,1.0,0.5] = 2.0+1.0 = 3.0. Q(S2,a=1,θ) = [1,1,1]·[2.0,1.0,0.5] = 2.0+1.0+0.5 = 3.5.
  3. SARSA (actual next action = 1): target = 4 + 0.5(3.5) = 5.75 → error = 5.75 − 2.0 = 3.75.
  4. Q-learning (max over both): MAX{3.0, 3.5} = 3.5 → target = 4 + 0.5(3.5) = 5.75 → error = 3.75.
(a) Both targets happen to be identical here (5.75, error 3.75), because the actual next action taken (1) is also the greedy/maximizing action. (b) θ1 update is the same for both: 2.0 + 0.5×3.75×1 = 3.875. Neither is "more optimistic" in this specific case — SARSA and Q-learning only diverge when the actually-taken next action is not the greedy one.

Key insight: this is a deliberately-designed "trick" question — students should recognize that the two methods coincide whenever the behavior policy happens to act greedily on that step.

Q5 [5M]. Suppose the true value of both actions at some state S′ is 1.0. Noisy estimates under θ: Q(S′,0)=0.4, Q(S′,1)=1.6. Independent estimates under θ′: Q′(S′,0)=0.9, Q′(S′,1)=0.6. (a) Compute the vanilla Q-learning bootstrapped value (the MAX). (b) Compute the Double Q-learning bootstrapped value. (c) Which is closer to the true value of 1.0, and why?

  1. Vanilla Q-learning: MAX{Q(S′,0), Q(S′,1)} = MAX{0.4, 1.6} = 1.6.
  2. Double Q-learning: select action via θ → argmax{0.4, 1.6} → action 1. Evaluate using θ′ at action 1 → Q′(S′,1) = 0.6.
(a) Vanilla Q-learning bootstrap = 1.6 (overestimates the true value of 1.0 by 0.6). (b) Double Q-learning bootstrap = 0.6 (underestimates by 0.4). (c) Double Q-learning's magnitude of error (0.4) is smaller than vanilla Q-learning's (0.6) in this example, and — more importantly — its error direction (underestimation) is the generally safer failure mode, since it doesn't reinforce over-confident, potentially wrong actions the way overestimation does.

Key insight: Double Q-learning doesn't guarantee it lands closer to the true value on every single instance — but it removes the systematic upward bias that vanilla Q-learning always has.

Q6 [5M]. Short answers. (a) [1.5] Why can't Gradient Monte Carlo be used for a continuing (never-terminating) task? (b) [1.5] What single change turns semi-gradient TD(0) into semi-gradient n-step TD? (c) [1] Why does DQN preprocess frames to 84×84 grayscale instead of using the full 210×160 color image directly? (d) [1] Name one concrete difference between coarse coding and tile coding.

  1. (a) Gradient Monte Carlo needs the true return Gt, which requires the episode to actually terminate; a continuing task never provides that signal.
  2. (b) Instead of bootstrapping after just 1 real step, bootstrap after n real steps — sum n real discounted rewards, then add γnv̂(St+n;θ) as the bootstrapped tail.
  3. (c) Reducing resolution and color channels drastically cuts the input size (and thus network compute/memory) while retaining the visual information actually needed to play the game.
  4. (d) Coarse coding uses arbitrary overlapping regions (e.g. circles) which can activate any number of features per state; tile coding structures this into offset grids where exactly one tile per tiling is active — a sparser, more computationally efficient special case.
(a) No terminal episode ⇒ no Gt. (b) Sum n real rewards before bootstrapping, instead of just 1. (c) Reduces computational/memory cost while preserving gameplay-relevant detail. (d) Coarse coding = arbitrary overlapping regions, any number active; tile coding = offset grids, exactly one active tile per tiling.

Key insight: (b) is the single most commonly mis-answered conceptual question in this chapter — students often describe n-step TD as "using a bigger learning rate," which is incorrect.

Pattern across this chapter

Three skills recur across every question type here: (1) computing v̂(s;θ) or Q(s,a;θ) via a dot product and applying the correct update rule (MC vs semi-gradient TD vs n-step); (2) correctly distinguishing the SARSA target (actual next action) from the Q-learning target (max over next actions); (3) the two-step Double Q-learning mechanic (select via one estimator, evaluate via the other). Drill those three and you cover the bulk of the exam surface for this chapter.
